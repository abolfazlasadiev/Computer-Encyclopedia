## راهنمای کامل و کاربردی Cron Jobs در لینوکس

**کرون (Cron)** یکی از قدیمی‌ترین و در عین حال قدرتمندترین ابزارهای زمان‌بندی در دنیای یونیکس و لینوکس است. با کمک کرون می‌توانید هر دستوری را در دقیقه، ساعت، روز، ماه یا روز هفتهٔ مشخص، به‌طور خودکار اجرا کنید. این ابزار ستون فقرات اتوماسیون در سرورها محسوب می‌شود و برای کارهایی مثل پشتیبان‌گیری، پاکسازی کش، ارسال گزارش و بروزرسانی کاربرد دارد.

در این مقاله، همه چیز را از پایه تا سطح حرفه‌ای، با زبانی ساده و ساختاری منظم مرور می‌کنیم.

---

### ۱. آشنایی با Crontab

برای تعریف کارهای زمان‌بندی‌شده، فایلی به نام **crontab** (مخفف Cron Table) ویرایش می‌شود. هر کاربر در سیستم، کرون‌تاب مخصوص به خود را دارد که با دستور زیر باز می‌شود:

```bash
crontab -e
```

اگر اولین بار است که این دستور را اجرا می‌کنید، سیستم از شما می‌خواهد یک ویرایشگر متن (مثل `nano` یا `vim`) انتخاب کنید.

> **نکته امنیتی:** برای مشاهدهٔ تسک‌های فعلی بدون ویرایش، از `crontab -l` و برای پاک کردن همهٔ تسک‌ها از `crontab -r` استفاده کنید.

---

### ۲. ساختار دقیق هر خط (فرمان زمان‌بندی)

هر خط در فایل کرون‌تاب از ۶ بخش تشکیل می‌شود (۵ بخش زمان + ۱ بخش دستور):

```text
command  day_of_week  month  day_of_month hour minut
```

| فیلد     | محدوده مجاز | توضیح                             |
| -------- | ----------- | --------------------------------- |
| دقیقه    | ۰ تا ۵۹     | دقیقهٔ اجرا                       |
| ساعت     | ۰ تا ۲۳     | ساعت اجرا (فرمت ۲۴ ساعته)         |
| روز ماه  | ۱ تا ۳۱     | روز موردنظر از ماه                |
| ماه      | ۱ تا ۱۲     | شماره ماه                         |
| روز هفته | ۰ تا ۷      | (۰ و ۷ هر دو به معنی یک‌شنبه است) |

**عملگرهای ویژه:**

- `*` : یعنی «همهٔ مقادیر» (مثلاً هر ساعت، هر روز)
- `,` : برای تعیین چند مقدار مجزا (مثل `1,15,30`)
- `-` : برای تعیین بازه (مثل `9-17` یعنی ساعت ۹ تا ۱۷)
- `/` : برای تعیین بازه‌های منظم (مثل `*/10` یعنی هر ۱۰ دقیقه)

---

### ۳. مثال‌های پرکاربرد و روزمره

برای درک بهتر، چند نمونهٔ رایج را با هم مرور می‌کنیم:

```bash
# اجرا هر روز ساعت ۲ بامداد (زمان ایده‌آل برای بکاپ)
0 2 * * * /usr/local/bin/backup.sh

# اجرا هر ۵ دقیقه یک بار (برای مانیتورینگ سبک)
*/5 * * * * /usr/bin/check_service.sh

# اجرا هر ساعت در دقیقهٔ ۱۵ و ۴۵ (دو بار در ساعت)
15,45 * * * * /path/to/script.py

# اجرا هر روز کاری (دوشنبه تا جمعه) ساعت ۸ صبح
0 8 * * 1-5 /usr/bin/send_report

# اجرا در اولین روز هر ماه، ساعت ۳ نیمه‌شب
30 3 1 * * /root/monthly_cleanup.sh

# اجرا در زمان بوت سیستم (فقط در برخی توزیع‌ها)
@reboot /usr/bin/start_my_service
```

### 4. نکات طلایی برای جلوگیری از خطاهای رایج

بیشتر مشکلات کرون به دلیل تفاوت محیط اجرایی آن با محیط ترمینال کاربر رخ می‌دهد. این ۴ نکته را جدی بگیرید:

**۱. همیشه از مسیرهای مطلق استفاده کنید**  
محیط `PATH` در کرون بسیار محدود است. به‌جای `backup.sh` بنویسید `/home/user/scripts/backup.sh`. همچنین اگر دستور خاصی مثل `mysqldump` نیاز دارید، مسیر کامل آن را بیابید (`which mysqldump`) و استفاده کنید.

**۲. متغیر PATH را در بالای فایل تنظیم کنید**  
برای راحتی، می‌توانید در خطوط اول کرون‌تاب، مسیرهای اصلی را تعریف کنید:

```bash
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin
```

**۳. خروجی را به لاگ هدایت کنید تا گم نشود**  
اگر خطایی رخ دهد و خروجی جایی نرود، متوجه نمی‌شوید. خروجی استاندارد و خطا را به یک فایل بفرستید:

```bash
0 3 * * * /script.sh >> /var/log/myscript.log 2>&1
```

**۴. از قفل (Lock) برای جلوگیری از تداخل استفاده کنید**  
اگر اسکریپت شما ممکن است بیش از یک دور اجرا طول بکشد، از دستور `flock` استفاده کنید تا دو نسخه هم‌زمان اجرا نشوند:

```bash
*/10 * * * * flock -n /tmp/myapp.lock /usr/bin/myapp
```

### 5. عیب‌یابی (وقتی تسک اجرا نمی‌شود)

اگر کرون شما کار نمی‌کند، این مراحل را به ترتیب بررسی کنید:

۱. **بررسی لاگ سیستم:** در بیشتر توزیع‌ها، لاگ کرون در این مسیر ذخیره می‌شود:

```bash
grep CRON /var/log/syslog
# یا
journalctl -u cron | tail -50
```

۲. **اجرای دستی اسکریپت:** قبل از قرار دادن در کرون، اسکریپت را در ترمینال اجرا کنید تا مطمئن شوید بدون خطا کار می‌کند.

۳. **مجوزهای اجرا:** مطمئن شوید اسکریپت با `chmod +x script.sh` اجرایی شده است.

۴. **منطقهٔ زمانی:** زمان سیستم را با `date` چک کنید تا مطمئن شوید سرور ساعت درستی را نشان می‌دهد.
