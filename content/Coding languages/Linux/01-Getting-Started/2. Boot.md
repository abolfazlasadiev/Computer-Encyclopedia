#  (فرآیند بوت در لینوکس) Boot

---

## معرفی و مرور کلی

**فرآیند بوت** (Boot Process) یکی از مهم‌ترین و بنیادی‌ترین مفاهیم در هر سیستم‌عاملی است. در لینوکس، این فرآیند دنباله‌ای از مراحل است که از لحظه روشن کردن کامپیوتر شروع می‌شود و تا زمانی که سیستم‌عامل کاملاً بارگذاری شده و آماده استفاده شود، ادامه می‌یابد. درک این فرآیند برای هر کاربر لینوکس ضروری است، زیرا به شما کمک می‌کند تا مشکلات راه‌اندازی را عیب‌یابی کنید، عملکرد بوت را بهینه کنید و درک عمیق‌تری از نحوه کار سیستم‌عامل داشته باشید.

در این مقاله جامع، تمام مراحل فرآیند بوت لینوکس را از لحظه فشار دادن دکمه پاور تا ورود به سیستم، گام‌به‌گام بررسی می‌کنیم.

---

## ۱. بوت چیست؟

**بوت** (Boot) که مخفف عبارت **Bootstrap** (بوت‌استرپ) است، به فرآیند راه‌اندازی یک کامپیوتر از حالت خاموش تا زمانی که سیستم‌عامل آماده استفاده شود، گفته می‌شود. این اصطلاح از عبارت "بالا کشیدن خود با بند کفش" (Pulling oneself up by one's bootstraps) گرفته شده است، زیرا سیستم باید خودش را از یک حالت خاموش به حالت اجرایی برساند.

### چرا به بوت نیاز داریم؟

- کامپیوترها در حالت خاموش، هیچ برنامه‌ای در حافظه ندارند
- برای اجرای سیستم‌عامل، باید آن را از دیسک به حافظه بارگذاری کرد
- این کار نیاز به یک برنامه کوچک (بوت‌لودر) دارد که خودش بارگذاری شود
- بوت‌لودر وظیفه بارگذاری سیستم‌عامل را بر عهده دارد

## ۲. مراحل فرآیند بوت در لینوکس

فرآیند بوت لینوکس به طور کلی به **۶ مرحله اصلی** تقسیم می‌شود:

```text
┌─────────────────────────────────────────────────────────────────────┐
│                    مراحل فرآیند بوت لینوکس                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  1.  BIOS/UEFI Initialization    (راه‌اندازی سخت‌افزار)           │
│         ↓                                                          │
│  2.  Bootloader                  (GRUB یا Systemd-boot)            │
│         ↓                                                          │
│  3.  Kernel Loading             (بارگذاری هسته)                   │
│         ↓                                                          │
│  4.  Initial RAM Disk           (بارگذاری ماژول‌های اولیه)        │
│         ↓                                                          │
│  5.  Init Process               (راه‌اندازی اولین فرآیند)          │
│         ↓                                                          │
│  6.  User Space                 (ورود به سیستم)                    │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## ۳. مرحله اول: BIOS/UEFI Initialization

### ۳.۱. BIOS چیست؟

**BIOS** (Basic Input/Output System) یک سیستم ورودی/خروجی پایه است که بر روی یک تراشه کوچک روی مادربرد قرار دارد. وظایف اصلی BIOS عبارتند از:

- **POST** (Power-On Self Test): بررسی سلامت سخت‌افزارها
- **شناسایی دستگاه‌ها**: تشخیص دیسک‌ها، رم، صفحه کلید، مانیتور و ...
- **انتخاب دستگاه بوت**: تعیین اینکه از کدام دستگاه (دیسک، فلش، شبکه) بوت شود
- **بارگذاری بوت‌لودر**: اجرای بوت‌لودر از دستگاه انتخاب شده

### ۳.۲. UEFI چیست؟

**UEFI** (Unified Extensible Firmware Interface) جایگزین مدرن BIOS است و مزایای زیر را دارد:

- پشتیبانی از دیسک‌های بزرگتر از ۲ ترابایت
- رابط گرافیکی (به جای صفحه‌آبی)
- سرعت بوت بالاتر
- پشتیبانی از Secure Boot
- قابلیت بوت از شبکه

### ۳.۳. مراحل POST

هنگامی که کامپیوتر را روشن می‌کنید:

۱. **بررسی منبع تغذیه**: اطمینان از تأمین برق مناسب
۲. **بررسی CPU**: تست پردازنده
۳. **بررسی RAM**: تست حافظه
۴. **بررسی دستگاه‌های ذخیره‌سازی**: شناسایی دیسک‌ها
۵. **بررسی دستگاه‌های ورودی/خروجی**: صفحه کلید، موس، مانیتور
۶. **تنظیمات اولیه**: مقداردهی اولیه دستگاه‌ها

اگر همه چیز سالم باشد، یک **بوق کوتاه** (Beep) شنیده می‌شود. در صورت مشکل، بوق‌های بلند یا متوالی شنیده می‌شود.

### ۳.۴. جدول کدهای بوق

| تعداد بوق | مشکل احتمالی |
|-----------|--------------|
| ۱ بوق کوتاه | سیستم سالم است |
| بوق‌های ممتد | مشکل در RAM |
| ۱ بوق بلند، ۱ بوق کوتاه | مشکل در مادربرد |
| ۱ بوق بلند، ۲ بوق کوتاه | مشکل در کارت گرافیک |

## ۴. مرحله دوم: بوت‌لودر (Bootloader)

### ۴.۱. بوت‌لودر چیست؟

**بوت‌لودر** (Bootloader) یک برنامه کوچک است که وظیفه بارگذاری هسته لینوکس را بر عهده دارد. این برنامه اولین نرم‌افزاری است که پس از POST اجرا می‌شود و معمولاً در بخش ابتدایی دیسک (MBR یا پارتیشن EFI) ذخیره می‌شود.

### ۴.۲. GRUB - محبوب‌ترین بوت‌لودر

**GRUB** (GRand Unified Bootloader) استانداردترین و محبوب‌ترین بوت‌لودر در لینوکس است. ویژگی‌های اصلی GRUB:

- **پشتیبانی از چندین سیستم‌عامل**: بوت دوگانه و چندگانه
- **پشتیبانی از انواع سیستم فایل**: ext4، btrfs، xfs، FAT، NTFS
- **رابط کاربری**: منوی گرافیکی یا متنی
- **قابلیت ویرایش**: امکان تغییر پارامترهای بوت قبل از اجرا
- **حالت Recovery**: دسترسی به حالت تعمیر

### ۴.۳. ساختار GRUB

```text
/boot/grub/
│
├── grub.cfg              ← فایل پیکربندی اصلی (به طور خودکار تولید می‌شود)
├── grubenv               ← متغیرهای محیطی
├── fonts/                ← فونت‌ها
├── locale/               ← فایل‌های زبان
└── themes/               ← تم‌های گرافیکی
```

**فایل‌های مهم GRUB**:

```text
/boot/grub/grub.cfg      ← فایل پیکربندی اصلی (دستکاری نکنید!)
/etc/default/grub        ← فایل پیکربندی برای تولید grub.cfg
```

### ۴.۴. دستورات مهم GRUB

**بروزرسانی GRUB**:

```bash
# بعد از تغییر /etc/default/grub
sudo update-grub          # در اوبونتو و دبیان
sudo grub-mkconfig -o /boot/grub/grub.cfg  # در فدورا و آرچ
```

**نصب GRUB روی دیسک**:

```bash
# نصب روی MBR (سیستم‌های قدیمی)
sudo grub-install /dev/sda

# نصب روی EFI (سیستم‌های جدید)
sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi
```

### ۴.۵. ویرایش پارامترهای بوت

در منوی GRUB، می‌توانید پارامترهای بوت را تغییر دهید:

1. وقتی منوی GRUB ظاهر شد، روی گزینه مورد نظر کلیک کنید و کلید **E** را فشار دهید
2. خط شروع با **linux** را پیدا کنید
3. پارامترهای مورد نظر را اضافه یا تغییر دهید:

```bash
# پارامترهای رایج
nomodeset        # برای مشکلات کارت گرافیک
acpi=off         # برای مشکلات مدیریت انرژی
noacpi           # برای مشکلات ACPI
3                # بوت در حالت Runlevel 3 (چندکاربره با شبکه، بدون GUI)
single           # حالت تک‌کاربره (ریکاوری)
```

4. برای بوت با پارامترهای جدید، **Ctrl+X** یا **F10** را فشار دهید

### ۴.۶. بوت‌لودرهای دیگر

| بوت‌لودر | توضیحات |
|----------|----------|
| **Systemd-boot** | بوت‌لودر ساده و سریع در سیستم‌های UEFI |
| **LILO** | بوت‌لودر قدیمی (تقریباً منسوخ شده) |
| **rEFInd** | بوت‌لودر زیبا و مدرن برای UEFI |
| **ELILO** | نسخه UEFI از LILO |
| **Syslinux** | بوت‌لودر سبک برای سیستم‌های نهفته |

## ۵. مرحله سوم: بارگذاری هسته (Kernel Loading)

پس از اینکه بوت‌لودر انتخاب شد، وظیفه بارگذاری **هسته لینوکس** (Linux Kernel) و **فایل سیستم اولیه** (initrd/initramfs) را بر عهده دارد.

### ۵.۱. بارگذاری هسته

۱. بوت‌لودر فایل هسته را از دیسک می‌خواند
۲. هسته در حافظه (RAM) بارگذاری می‌شود
۳. بوت‌لودر کنترل را به هسته می‌سپارد
۴. هسته شروع به اجرا می‌کند

### ۵.۲. فایل‌های هسته

```text
/boot/
│
├── vmlinuz-6.8.0-45-generic      ← هسته فشرده شده
├── initrd.img-6.8.0-45-generic   ← Initial RAM Disk
├── System.map-6.8.0-45-generic   ← نقشه نمادها (برای دیباگ)
└── config-6.8.0-45-generic       ← پیکربندی هسته
```

### ۵.۳. نسخه‌های هسته

```bash
# مشاهده نسخه هسته فعلی
uname -r
# خروجی: 6.8.0-45-generic

# مشاهده اطلاعات کامل هسته
uname -a
# خروجی: Linux hostname 6.8.0-45-generic #46-Ubuntu SMP ... x86_64 GNU/Linux
```

## ۶. مرحله چهارم: Initial RAM Disk (initrd/initramfs)

### ۶.۱. initramfs چیست؟

**initramfs** (Initial RAM File System) یک سیستم فایل موقت است که در حافظه (RAM) بارگذاری می‌شود و شامل ماژول‌های ضروری هسته است که برای دسترسی به دیسک اصلی مورد نیاز هستند.

### ۶.۲. چرا به initramfs نیاز داریم؟

- هسته لینوکس ممکن است درایورهای دیسک را نداشته باشد
- برای خواندن دیسک اصلی، نیاز به درایورهای خاص است
- initramfs این درایورها را فراهم می‌کند
- پس از بارگذاری درایورها، سیستم فایل اصلی نصب (Mount) می‌شود

### ۶.۳. محتوای initramfs

```text
initramfs/
│
├── bin/          ← دستورات پایه
├── dev/          ← دستگاه‌ها
├── etc/          ← پیکربندی‌ها
├── lib/          ← کتابخانه‌ها و ماژول‌های هسته
├── proc/         ← سیستم فایل proc
├── sbin/         ← دستورات مدیریتی
├── sys/          ← سیستم فایل sys
├── tmp/          ← فایل‌های موقت
└── init          ← اسکریپت اولیه
```

### ۶.۴. بازسازی initramfs

```bash
# در اوبونتو/دبیان
sudo update-initramfs -u

# در فدورا
sudo dracut --force

# در آرچ
sudo mkinitcpio -p linux
```

## ۷. مرحله پنجم: فرآیند Init

پس از بارگذاری هسته و initramfs، اولین فرآیند سیستم‌عامل شروع به کار می‌کند. این فرآیند **Init** نام دارد و **PID 1** (Process ID 1) به آن اختصاص می‌یابد.

### ۷.۱. سیستم‌های Init

| سیستم Init | توضیحات | توزیع‌ها |
|------------|---------|----------|
| **Systemd** | مدرن‌ترین و محبوب‌ترین | اوبونتو، فدورا، آرچ، دبیان (جدید) |
| **SysV Init** | سیستم سنتی یونیکس | دبیان (قدیمی)، اسلک‌ور |
| **OpenRC** | سیستم سبک | گنتی، آرتیکس لینوکس |
| **Upstart** | سیستم اوبونتو (منسوخ) | اوبونتو (تا نسخه ۱۴.۰۴) |

### ۷.۲. Systemd - استاندارد مدرن

**Systemd** یک سیستم مدیریت سرویس‌ها و Init مدرن است که اکثر توزیع‌های لینوکس از آن استفاده می‌کنند.

**واحدهای Systemd** (Units):
- **Service (.service)**: سرویس‌ها (مثل Apache، SSH)
- **Target (.target)**: گروه‌هایی از واحدها (مثل graphical.target)
- **Timer (.timer)**: زمان‌بندی‌ها (مثل cron)
- **Mount (.mount)**: نقاط نصب
- **Socket (.socket)**: سوکت‌های شبکه

**Targetهای اصلی**:

| Target | توضیحات |
|--------|----------|
| **poweroff.target** | خاموش کردن سیستم |
| **rescue.target** | حالت تکراه‌بر (تک‌کاربره) |
| **multi-user.target** | حالت چندکاربره (بدون GUI) |
| **graphical.target** | حالت چندکاربره با GUI |
| **reboot.target** | راه‌اندازی مجدد |

**دستورات Systemd**:

```bash
# مدیریت سرویس‌ها
sudo systemctl start ssh       # شروع سرویس
sudo systemctl stop ssh        # توقف سرویس
sudo systemctl restart ssh     # راه‌اندازی مجدد
sudo systemctl status ssh      # وضعیت سرویس
sudo systemctl enable ssh      # فعال‌سازی در بوت
sudo systemctl disable ssh     # غیرفعال‌سازی در بوت
sudo systemctl is-enabled ssh  # بررسی فعال‌سازی

# مدیریت سیستم
sudo systemctl reboot          # راه‌اندازی مجدد
sudo systemctl poweroff        # خاموش کردن
sudo systemctl suspend         # خوابیدن
sudo systemctl hibernate       # خواب زمستانی

# مشاهده گزارش‌ها
sudo journalctl -u ssh         # گزارش‌های سرویس SSH
sudo journalctl -f             # مشاهده زنده گزارش‌ها
```

### ۷.۳. فرآیند Init با Systemd

1. Systemd به عنوان **PID 1** شروع می‌شود
2. Systemd **target default** را می‌خواند (مثلاً graphical.target)
3. Systemd تمام واحدهای وابسته را شروع می‌کند
4. Systemd به طور موازی سرویس‌ها را راه‌اندازی می‌کند (افزایش سرعت بوت)
5. پس از اتمام، سیستم آماده استفاده است

### ۷.۴. بررسی زمان بوت

```bash
# زمان کل بوت
systemd-analyze time
# خروجی: Startup finished in 5.123s (firmware) + 2.456s (loader) + 8.789s (kernel) + 12.345s (userspace)

# زمان‌بندی دقیق سرویس‌ها
systemd-analyze blame
# خروجی: لیست سرویس‌ها بر اساس زمان بوت

# گراف وابستگی‌ها
systemd-analyze plot > boot.svg
# تولید یک فایل گرافیکی از وابستگی‌ها
```

## ۸. مرحله ششم: فضای کاربری (User Space)

پس از اتمام فرآیند Init، سیستم وارد **فضای کاربری** (User Space) می‌شود.

### ۸.۱. حالت‌های ورود

**۱. ورود از طریق ترمینال**:

```text
Ubuntu 24.04 LTS hostname tty1
hostname login: _
```

- کاربر نام کاربری و رمز عبور را وارد می‌کند
- پس از ورود، به Shell دسترسی پیدا می‌کند
- معمولاً با فشار دادن **Ctrl+Alt+F1 تا F6** به ترمینال‌های متنی دسترسی دارید

**۲. ورود از طریق رابط گرافیکی** (Display Manager):

- صفحه نمایشگر (Display Manager) ظاهر می‌شود
- کاربر نام کاربری و رمز عبور را وارد می‌کند
- پس از ورود، محیط دسکتاپ (Desktop Environment) بارگذاری می‌شود

### ۸.۲. Display Manager

**Display Manager** برنامه‌ای است که صفحه ورود گرافیکی را نمایش می‌دهد:

| Display Manager | توضیحات |
|-----------------|----------|
| **GDM** (GNOME Display Manager) | پیش‌فرض اوبونتو و GNOME |
| **SDDM** (Simple Desktop Display Manager) | پیش‌فرض KDE |
| **LightDM** | پیش‌فرض Xubuntu و Lubuntu |
| **XDM** (X Display Manager) | قدیمی‌ترین |

## ۹. عیب‌یابی بوت

### ۹.۱. مشکلات رایج بوت

**۱. صفحه سیاه بعد از GRUB**

علت: مشکل در کارت گرافیک یا درایور

راه حل:
```bash
# در GRUB، روی گزینه Linux کلیک کنید و E را بزنید
# پارامتر quiet splash را حذف کنید و nomodeset را اضافه کنید
# Ctrl+X برای بوت

# پس از ورود به سیستم، درایور کارت گرافیک را نصب کنید
```

**۲. پیام "Kernel Panic"**

علت: مشکل در هسته یا سخت‌افزار

راه حل:
```bash
# از هسته قبلی در منوی GRUB استفاده کنید
# Advanced Options → Kernel (older version)
```

**۳. مشکل در Mount کردن دیسک**

علت: مشکل در /etc/fstab یا سیستم فایل

راه حل:
```bash
# ورود به حالت Recovery
# fsck /dev/sda1 (بررسی سیستم فایل)
```

**۴. بوت در حالت Emergency**

علت: مشکل در یکی از سرویس‌ها

راه حل:
```bash
# بررسی سرویس‌های مشکل‌دار
systemctl --failed

# غیرفعال کردن سرویس مشکل‌دار
sudo systemctl disable problematic-service
```

### ۹.۲. حالت‌های ریکاوری

**۱. Recovery Mode از GRUB**:

- از منوی GRUB، Advanced Options را انتخاب کنید
- سپس Recovery Mode را انتخاب کنید
- گزینه‌های موجود:

```text
resume        ← ادامه بوت عادی
clean         ← پاکسازی فایل‌های موقت
dpkg          ← تعمیر بسته‌های خراب
fsck          ← بررسی سیستم فایل
grub          ← تعمیر GRUB
network       ← فعال‌سازی شبکه
root          ← دسترسی به Shell با دسترسی ریشه
system-summary ← خلاصه سیستم
```

**۲. حالت تک‌کاربره** (Single User Mode):

```bash
# در GRUB، پارامتر single یا 1 را اضافه کنید
linux /vmlinuz root=/dev/sda1 single
```

### ۹.۳. ابزارهای عیب‌یابی

**۱. بررسی گزارش‌های بوت**:

```bash
# گزارش‌های هسته
dmesg | less

# گزارش‌های سیستم (Systemd)
journalctl -b | less

# گزارش‌های بوت (سیستم‌های قدیمی)
less /var/log/boot.log
```

## خلاصه و نتیجه‌گیری

فرآیند بوت لینوکس یک دنباله منظم از مراحل است:

| مرحله | توضیحات |
|-------|----------|
| **BIOS/UEFI** | راه‌اندازی سخت‌افزار، POST، انتخاب دستگاه بوت |
| **Bootloader** | بارگذاری GRUB، نمایش منو، انتخاب هسته |
| **Kernel** | بارگذاری هسته در RAM، مقداردهی اولیه |
| **initramfs** | بارگذاری ماژول‌های ضروری، نصب دیسک اصلی |
| **Init (Systemd)** | شروع PID 1، راه‌اندازی سرویس‌ها |
| **User Space** | ورود کاربر، بارگذاری محیط دسکتاپ |

درک این مراحل به شما کمک می‌کند تا:

- مشکلات بوت را عیب‌یابی کنید
- زمان بوت را بهینه کنید
- تنظیمات بوت را شخصی‌سازی کنید
- درک عمیق‌تری از سیستم‌عامل داشته باشید

## سؤالات متداول

**سؤال: تفاوت GRUB و Systemd-boot چیست؟**  
GRUB قدیمی‌تر و قدرتمندتر است و از سیستم‌های BIOS و UEFI پشتیبانی می‌کند. Systemd-boot ساده‌تر و سبک‌تر است و فقط برای UEFI طراحی شده است.

**سؤال: چگونه بوت دوگانه (Dual Boot) را تنظیم کنم؟**  
GRUB به طور خودکار ویندوز را شناسایی می‌کند. اگر نه، دستور `sudo update-grub` را اجرا کنید.

**سؤال: Secure Boot چیست و آیا باید آن را غیرفعال کنم؟**  
Secure Boot یک ویژگی امنیتی در UEFI است. اکثر توزیع‌های مدرن (مانند اوبونتو و فدورا) از آن پشتیبانی می‌کنند، اما اگر مشکلی در بوت داشتید، می‌توانید آن را غیرفعال کنید.

**سؤال: تفاوت initramfs و initrd چیست؟**  
هر دو یک مفهوم هستند. initramfs نسخه مدرن‌تر است و از سیستم فایل cpio استفاده می‌کند، در حالی که initrd از یک تصویر دیسک استفاده می‌کند.

**سؤال: چگونه GRUB را تعمیر کنم؟**  
با استفاده از Live USB و دستور `boot-repair` یا با اجرای `sudo grub-install /dev/sda` و `sudo update-grub`.

## مفاهیم مرتبط

- **BIOS/UEFI**: سیستم ورودی/خروجی پایه
- **GRUB**: بوت‌لودر استاندارد لینوکس
- **Systemd**: سیستم مدیریت سرویس‌ها و Init
- **Kernel**: هسته سیستم‌عامل
- **initramfs**: سیستم فایل موقت در RAM
- **PID 1**: اولین فرآیند سیستم (Systemd یا Init)
- **Recovery Mode**: حالت تعمیر و ریکاوری
