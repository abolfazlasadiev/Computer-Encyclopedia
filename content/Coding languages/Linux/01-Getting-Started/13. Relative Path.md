#  (مسیر نسبی در لینوکس) - Relative Path

---

## معرفی و مرور کلی

**مسیر نسبی** (Relative Path) در لینوکس، یک آدرس کوتاه‌شده برای اشاره به فایل‌ها و دایرکتوری‌ها است که نسبت به **دایرکتوری فعلی** (Current Working Directory) شما تعریف می‌شود. برخلاف مسیر مطلق که از ریشه سیستم (`/`) شروع می‌شود، مسیر نسبی از موقعیت فعلی شما آغاز می‌گردد و با استفاده از نمادهای خاص مانند نقطه (`.`) و دو نقطه (`..`)، به شما امکان می‌دهد تا به سرعت و به سادگی در ساختار سیستم فایل حرکت کنید و به فایل‌ها و دایرکتوری‌های اطراف دسترسی پیدا کنید.

درک مسیرهای نسبی، یکی از مهارت‌های اساسی و روزمره در کار با لینوکس است. استفاده از مسیرهای نسبی، تایپ دستورات را کوتاه‌تر، سریع‌تر و خوانا‌تر می‌کند و به شما امکان می‌دهد تا بدون نیاز به تایپ مسیرهای طولانی، به راحتی با سیستم کار کنید.

## ۱. مسیر نسبی چیست و چه ویژگی‌هایی دارد؟

### ۱.۱. تعریف دقیق

**مسیر نسبی** (Relative Path) یا **مسیر وابسته**، رشته‌ای است که برای اشاره به یک فایل یا دایرکتوری، نسبت به **دایرکتوری کاری فعلی** (Current Working Directory) شما استفاده می‌شود. این مسیر، برخلاف مسیر مطلق که از ریشه شروع می‌شود، هیچ‌گونه اطلاعاتی درباره ریشه سیستم ندارد و فقط موقعیت هدف را نسبت به موقعیت فعلی شما توصیف می‌کند.

### ۱.۲. ویژگی‌های کلیدی

- **شروع بدون ریشه**: بر خلاف مسیر مطلق که با `/` شروع می‌شود، مسیر نسبی با نام یک دایرکتوری، یک فایل، یا نمادهای خاص مانند `.` یا `..` شروع می‌گردد.
- **وابستگی به موقعیت**: مسیر نسبی به شدت به دایرکتوری فعلی شما وابسته است. با تغییر دایرکتوری، مفهوم یک مسیر نسبی خاص نیز تغییر می‌کند.
- **کوتاهی و سادگی**: مسیرهای نسبی معمولاً بسیار کوتاه‌تر از مسیرهای مطلق هستند و تایپ آنها سریع‌تر و آسان‌تر است.
- **انعطاف‌پذیری**: اگر ساختار دایرکتوری‌های شما تغییر کند (مثلاً یک پروژه را به مکان دیگری منتقل کنید)، مسیرهای نسبی همچنان کار می‌کنند، در حالی که مسیرهای مطلق خراب می‌شوند.
- **قابلیت حمل**: اسکریپت‌هایی که از مسیرهای نسبی استفاده می‌کنند، معمولاً قابل حمل‌تر هستند و روی سیستم‌های مختلف با ساختار دایرکتوری متفاوت کار می‌کنند.

### ۱.۳. ساختار کلی

یک مسیر نسبی از بخش‌های زیر تشکیل شده است:

```text
[نمادهای خاص مانند .. یا .]/[نام دایرکتوری]/[نام دایرکتوری]/[نام فایل یا دایرکتوری هدف]
```

**مثال‌های کامل**:

```text
Documents/report.pdf
../project/src/main.py
./script.sh
../../etc/hosts
```

## ۲. نمادهای خاص در مسیرهای نسبی

### ۲.۱. `.` (دایرکتوری فعلی)

**تعریف**: نماد نقطه (Dot) به **دایرکتوری فعلی** (Current Directory) شما اشاره دارد. این نماد معمولاً برای اجرای برنامه‌ها یا اسکریپت‌هایی که در دایرکتوری فعلی قرار دارند، استفاده می‌شود.

**کاربردها**:

```bash
# اجرای یک اسکریپت در دایرکتوری فعلی
./script.sh

# کپی فایل به دایرکتوری فعلی
cp /home/amir/file.txt .

# لیست کردن دایرکتوری فعلی (معادل ls بدون آرگومان)
ls .

# اجرای یک برنامه کامپایل شده در دایرکتوری فعلی
./my_program
```

**نکته**: در بسیاری از موارد، استفاده از `.` اختیاری است. برای مثال، `ls .` معادل `ls` است و `./script.sh` معادل `script.sh` نیست، زیرا به طور پیش‌فرض، سیستم در دایرکتوری فعلی به دنبال دستورات نمی‌گردد.

### ۲.۲. `..` (دایرکتوری والد)

**تعریف**: دو نقطه (Double Dot) به **دایرکتوری والد** (Parent Directory) یا یک سطح بالاتر از دایرکتوری فعلی اشاره دارد. با تکرار `..`، می‌توانید چندین سطح به بالا بروید.

**کاربردها**:

```bash
# رفتن به یک سطح بالاتر
cd ..

# رفتن به دو سطح بالاتر
cd ../..

# کپی فایل از دایرکتوری والد
cp ../file.txt .

# لیست کردن دایرکتوری والد
ls ..

# دسترسی به فایل در دایرکتوری والد
cat ../config/settings.ini
```

**مثال عملی**: فرض کنید در مسیر `/home/amir/Documents/project` قرار دارید:

```bash
cd ..          # رفتن به /home/amir/Documents
cd ../..       # رفتن به /home/amir
cd ../../..    # رفتن به /home
```

### ۲.۳. `~` (دایرکتوری خانه)

**تعریف**: علامت تیلد (Tilde) به **دایرکتوری خانه کاربر فعلی** (Home Directory) اشاره دارد. اگرچه `~` به طور دقیق یک مسیر نسبی نیست (زیرا به جای یک مسیر نسبی، به یک متغیر محیطی ارجاع می‌دهد)، اما در عمل به عنوان یک میانبر برای مسیر مطلق خانه کاربر استفاده می‌شود.

**کاربردها**:

```bash
# رفتن به دایرکتوری خانه
cd ~

# دسترسی به فایل در دایرکتوری خانه
cat ~/.bashrc

# کپی فایل به دایرکتوری خانه
cp file.txt ~/

# دسترسی به دایرکتوری خانه کاربر دیگر
cd ~another_user
```

### ۲.۴. `-` (دایرکتوری قبلی)

**تعریف**: علامت خط تیره (Dash) به **دایرکتوری قبلی** (Previous Directory) که در آن بودید اشاره دارد و به شما امکان می‌دهد به سرعت بین دو دایرکتوری جابه‌جا شوید.

**کاربردها**:

```bash
# رفتن به دایرکتوری قبلی
cd -

# مثال کاربردی
cd /etc           # رفتن به /etc
cd /home          # رفتن به /home
cd -              # بازگشت به /etc
cd -              # بازگشت به /home
```

## ۳. نحوه استفاده از مسیرهای نسبی در دستورات

### ۳.۱. دستور `cd` (Change Directory)

```bash
# رفتن به یک دایرکتوری در سطح فعلی
cd Documents

# رفتن به یک دایرکتوری در سطح بالاتر
cd ../project

# رفتن به یک دایرکتوری در سطح پایین‌تر
cd Documents/project/src

# رفتن به دایرکتوری خانه
cd ~

# رفتن به دایرکتوری قبلی
cd -

# رفتن به دایرکتوری والد از هر جایی
cd ../..
```

### ۳.۲. دستور `ls` (List)

```bash
# لیست کردن دایرکتوری فعلی
ls

# لیست کردن یک دایرکتوری در سطح فعلی
ls Documents

# لیست کردن دایرکتوری والد
ls ..

# لیست کردن یک دایرکتوری در سطح بالاتر
ls ../project

# لیست کردن با جزئیات
ls -la ./src
```

### ۳.۳. دستور `cp` (Copy)

```bash
# کپی فایل به دایرکتوری فعلی
cp /home/amir/file.txt .

# کپی فایل به یک دایرکتوری در سطح فعلی
cp file.txt Documents/

# کپی فایل از دایرکتوری والد
cp ../file.txt .

# کپی فایل به دایرکتوری بالاتر
cp file.txt ../

# کپی چندین فایل با مسیر نسبی
cp *.txt ../backup/
```

### ۳.۴. دستور `mv` (Move/Rename)

```bash
# جابجایی فایل به دایرکتوری در سطح فعلی
mv file.txt Documents/

# جابجایی فایل به دایرکتوری بالاتر
mv file.txt ../

# تغییر نام با مسیر نسبی
mv old.txt new.txt

# جابجایی فایل از دایرکتوری والد
mv ../file.txt .
```

### ۳.۵. دستور `rm` (Remove)

```bash
# حذف فایل در دایرکتوری فعلی
rm file.txt

# حذف فایل در دایرکتوری زیر
rm Documents/file.txt

# حذف فایل در دایرکتوری بالاتر
rm ../file.txt

# حذف چندین فایل با wildcard
rm *.tmp
```

### ۳.۶. دستور `mkdir` (Make Directory)

```bash
# ایجاد دایرکتوری در سطح فعلی
mkdir new_project

# ایجاد دایرکتوری در یک سطح پایین‌تر
mkdir Documents/new_project

# ایجاد دایرکتوری‌های تو در تو
mkdir -p project/src/bin

# ایجاد دایرکتوری در دایرکتوری والد
mkdir ../backup
```

## ۴. مقایسه مسیر نسبی با مسیر مطلق

### ۴.۱. مثال‌های مقایسه‌ای

فرض کنید دایرکتوری فعلی شما `/home/amir/Documents/project` است.

| نوع مسیر | دستور | معادل مسیر مطلق |
|----------|-------|-----------------|
| **نسبی** | `ls src/` | `ls /home/amir/Documents/project/src` |
| **نسبی** | `cat ../file.txt` | `cat /home/amir/Documents/file.txt` |
| **نسبی** | `cd ../..` | `cd /home/amir` |
| **نسبی** | `./script.sh` | `/home/amir/Documents/project/script.sh` |
| **مطلق** | `ls /etc` | `ls /etc` (همان) |
| **مطلق** | `cat /home/amir/file.txt` | `cat /home/amir/file.txt` (همان) |

### ۴.۲. جدول مقایسه

| ویژگی | مسیر نسبی | مسیر مطلق |
|--------|------------|------------|
| **شروع** | بدون `/` | با `/` شروع می‌شود |
| **وابستگی** | وابسته به دایرکتوری فعلی | مستقل از دایرکتوری فعلی |
| **یکتایی** | ممکن است مبهم باشد | کاملاً یکتا |
| **طول** | کوتاه‌تر | بلندتر |
| **کاربرد** | کار روزمره، ترمینال | اسکریپت‌ها، پیکربندی‌ها |
| **انعطاف‌پذیری** | بالا (با جابجایی پروژه کار می‌کند) | پایین (با جابجایی خراب می‌شود) |
| **قابلیت حمل** | بالا | پایین |
| **احتمال خطا** | بیشتر (به دلیل وابستگی) | کمتر (دقیق و بدون ابهام) |

### ۴.۳. مزایا و معایب

**مزایای مسیر نسبی**:
- کوتاه‌تر و سریع‌تر برای تایپ
- انعطاف‌پذیرتر در برابر تغییرات ساختار
- قابلیت حمل بالا در اسکریپت‌ها
- بصری و قابل درک (نشان می‌دهد که هدف نسبت به موقعیت فعلی کجاست)

**معایب مسیر نسبی**:
- وابسته به دایرکتوری فعلی
- ممکن است مبهم باشد
- در اسکریپت‌ها ممکن است به نتایج غیرمنتظره منجر شود
- در فایل‌های پیکربندی قابل اعتماد نیست

## ۵. مسیرهای نسبی در اسکریپت‌نویسی

### ۵.۱. اهمیت مسیرهای نسبی در اسکریپت‌ها

در اسکریپت‌نویسی، مسیرهای نسبی می‌توانند مفید باشند، اما باید با دقت استفاده شوند. مزیت اصلی آنها **قابلیت حمل** (Portability) است: یک اسکریپت که از مسیرهای نسبی استفاده می‌کند، روی هر سیستمی که ساختار دایرکتوری مشابهی داشته باشد، کار می‌کند.

### ۵.۲. مثال اسکریپت با مسیرهای نسبی

**فایل `deploy.sh`**:

```bash
#!/bin/bash

# مسیرهای نسبی
SCRIPT_DIR="$(dirname "$0")"
CONFIG_DIR="./config"
LOG_DIR="./logs"
BIN_DIR="./bin"

# ایجاد دایرکتوری‌ها (نسبت به محل اسکریپت)
mkdir -p "$SCRIPT_DIR/$CONFIG_DIR"
mkdir -p "$SCRIPT_DIR/$LOG_DIR"
mkdir -p "$SCRIPT_DIR/$BIN_DIR"

# کپی فایل‌ها با مسیرهای نسبی
cp "$SCRIPT_DIR/../common/config.ini" "$SCRIPT_DIR/$CONFIG_DIR/"
cp "$SCRIPT_DIR/src/main.sh" "$SCRIPT_DIR/$BIN_DIR/"

# اجرا با مسیر نسبی
"$SCRIPT_DIR/$BIN_DIR/main.sh"
```

### ۵.۳. دریافت دایرکتوری اسکریپت

```bash
#!/bin/bash

# دریافت مسیر نسبی اسکریپت
SCRIPT_PATH="$(dirname "$0")"
echo "Script relative path: $SCRIPT_PATH"

# دریافت مسیر مطلق (تبدیل از نسبی)
SCRIPT_ABSOLUTE="$(cd "$(dirname "$0")" && pwd)"
echo "Script absolute path: $SCRIPT_ABSOLUTE"

# استفاده از مسیرهای نسبی بر اساس مکان اسکریپت
PROJECT_ROOT="$SCRIPT_ABSOLUTE/../.."
echo "Project root: $PROJECT_ROOT"
```

### ۵.۴. کار با مسیرهای نسبی در اسکریپت

```bash
#!/bin/bash

# بررسی اینکه آیا یک مسیر، نسبی است یا مطلق
is_relative() {
    [[ "$1" != /* ]]
}

# تبدیل مسیر نسبی به مطلق
to_absolute() {
    if is_relative "$1"; then
        echo "$(pwd)/$1"
    else
        echo "$1"
    fi
}

# مثال
RELATIVE_PATH="./file.txt"
ABSOLUTE_PATH=$(to_absolute "$RELATIVE_PATH")
echo "Relative: $RELATIVE_PATH"
echo "Absolute: $ABSOLUTE_PATH"
```

## ۶. عیب‌یابی مسیرهای نسبی

### ۶.۱. خطای "No such file or directory"

این خطا زمانی رخ می‌دهد که مسیر نسبی شما به یک فایل یا دایرکتوری که نسبت به دایرکتوری فعلی وجود ندارد، اشاره می‌کند.

```bash
# اشتباه ❌
cat Documents/nonexistent.txt
# خروجی: cat: Documents/nonexistent.txt: No such file or directory

# راه‌حل: بررسی دایرکتوری فعلی
pwd
ls Documents/
```

### ۶.۲. اشتباه در تعداد `..`

```bash
# فرض کنید در /home/amir/Documents هستید
cd ../..      # می‌روید به /home
cd ../../..   # می‌روید به / (ریشه)
cd ../../../.. # می‌روید به / (همان ریشه، خطایی ندارد)
```

### ۶.۳. فراموش کردن `/` در ابتدای مسیر

```bash
# اشتباه ❌ (به جای مسیر مطلق، یک مسیر نسبی در نظر گرفته می‌شود)
cat etc/hosts
# این به دنبال etc/hosts در دایرکتوری فعلی می‌گردد

# درست ✅
cat /etc/hosts
```

### ۶.۴. استفاده نادرست از `.`

```bash
# اشتباه ❌ (نقطه به تنهایی قابل استفاده نیست)
cd .

# درست ✅
./script.sh
```

### ۶.۵. بررسی مسیرهای نسبی

```bash
# بررسی اینکه آیا یک مسیر، مطلق است یا نسبی
if [[ "$path" == /* ]]; then
    echo "Absolute path"
else
    echo "Relative path"
fi

# نمایش مسیر مطلق معادل یک مسیر نسبی
realpath ./file.txt
```

## ۷. تمرین‌های عملی

### ۷.۱. تمرین ساده

```bash
# 1. نمایش دایرکتوری فعلی
pwd

# 2. ایجاد یک دایرکتوری به نام practice
mkdir practice

# 3. رفتن به دایرکتوری practice
cd practice

# 4. ایجاد فایل در دایرکتوری فعلی
touch file1.txt file2.txt

# 5. نمایش فایل‌ها با مسیر نسبی
ls .

# 6. رفتن به دایرکتوری والد
cd ..

# 7. حذف دایرکتوری practice با مسیر نسبی
rm -rf practice
```

### ۷.۲. تمرین پیشرفته

```bash
# 1. ایجاد یک ساختار دایرکتوری پیچیده
mkdir -p project/{src,bin,doc,log}
touch project/src/main.py
touch project/README.md

# 2. رفتن به دایرکتوری src
cd project/src

# 3. مشاهده فایل با مسیر نسبی
cat ../README.md

# 4. کپی فایل به دایرکتوری doc با مسیر نسبی
cp ../README.md ../doc/

# 5. ایجاد یک اسکریپت با مسیرهای نسبی
cat > ../bin/build.sh << 'EOF'
#!/bin/bash
echo "Building from: $(pwd)"
cd ../src
echo "Now in: $(pwd)"
ls -la
EOF

# 6. اجرای اسکریپت با مسیر نسبی
../bin/build.sh

# 7. رفتن به دایرکتوری root پروژه و حذف
cd ../../
rm -rf project
```

### ۷.۳. تمرین با `..`

```bash
# 1. رفتن به دایرکتوری /etc
cd /etc

# 2. رفتن به دایرکتوری /home با مسیر نسبی
cd ../home

# 3. رفتن به دایرکتوری /root با مسیر نسبی (اگر دسترسی دارید)
cd ../root

# 4. رفتن به دایرکتوری /var/log با مسیر نسبی از /home
cd ../var/log

# 5. بازگشت به دایرکتوری قبلی
cd -
```

## ۸. خلاصه و نتیجه‌گیری

### ۸.۱. نکات کلیدی

- **مسیر نسبی** از دایرکتوری فعلی شروع می‌شود و نسبت به آن تعریف می‌شود.
- **ویژگی اصلی** مسیر نسبی، وابستگی آن به موقعیت فعلی کاربر است.
- **نمادهای خاص** مسیرهای نسبی عبارتند از: `.` (دایرکتوری فعلی)، `..` (دایرکتوری والد)، `~` (دایرکتوری خانه)، و `-` (دایرکتوری قبلی).
- مسیرهای نسبی برای **کار روزمره** در ترمینال و **اسکریپت‌های قابل حمل** بسیار مفید هستند.
- برای **پیکربندی سیستم** و **اسکریپت‌های حیاتی**، بهتر است از مسیرهای مطلق استفاده کنید.

### ۸.۲. فرمول ساده

```text
مسیر نسبی = [. یا .. یا نام دایرکتوری] + / + [نام دایرکتوری] + ... + / + [نام هدف]
```

**مثال‌ها**:

```text
Documents/file.txt          # فایل در دایرکتوری Documents در مسیر فعلی
../src/main.py              # فایل در دایرکتوری src در سطح بالاتر
./script.sh                 # فایل در دایرکتوری فعلی
../../etc/hosts             # دو سطح بالا و سپس دایرکتوری etc
```

### ۸.۳. دستورات مفید

| دستور | توضیحات |
|--------|----------|
| `pwd` | نمایش مسیر مطلق دایرکتوری فعلی |
| `cd .` | تغییر به دایرکتوری فعلی (کاری نمی‌کند) |
| `cd ..` | رفتن به یک سطح بالاتر |
| `realpath` | تبدیل مسیر نسبی به مطلق |
| `cd -` | رفتن به دایرکتوری قبلی |

## سؤالات متداول

**سؤال: تفاوت مسیر نسبی و مطلق چیست؟**  
مسیر نسبی از دایرکتوری فعلی شروع می‌شود و به آن وابسته است، در حالی که مسیر مطلق از ریشه سیستم (`/`) شروع می‌شود و مستقل از موقعیت فعلی است.

**سؤال: چه زمانی باید از مسیر نسبی استفاده کنم؟**  
در کار روزمره با ترمینال، برای دسترسی به فایل‌های نزدیک، و در اسکریپت‌هایی که نیاز به قابلیت حمل دارند.

**سؤال: `..` در مسیر نسبی به چه معناست؟**  
`..` به دایرکتوری والد (یک سطح بالاتر) اشاره دارد.

**سؤال: چگونه مسیر نسبی را به مطلق تبدیل کنم؟**  
با استفاده از دستور `realpath ./path` یا `readlink -f ./path`.

**سؤال: آیا می‌توانم از چندین `..` پشت سر هم استفاده کنم؟**  
بله، مانند `cd ../../..` که سه سطح به بالا می‌رود.

**سؤال: اگر بیش از حد از `..` استفاده کنم، چه اتفاقی می‌افتد؟**  
به ریشه سیستم (`/`) می‌رسید و دیگر نمی‌توانید بالاتر بروید.

## مفاهیم مرتبط

- **مسیر مطلق (Absolute Path)**: مسیری که از ریشه سیستم شروع می‌شود
- **دایرکتوری فعلی (Current Directory)**: دایرکتوری که در آن قرار دارید
- **دایرکتوری والد (Parent Directory)**: دایرکتوری یک سطح بالاتر
- **دایرکتوری خانه (Home Directory)**: دایرکتوری شخصی کاربر
- **سیستم فایل (Filesystem)**: ساختار سازماندهی فایل‌ها و دایرکتوری‌ها
