# انتیتی Entity در VHDL — تحلیل جامع و عمیق

## مقدمه: درگاه ورود به دنیای سخت‌افزار

در VHDL، **Entity** اولین و مهم‌ترین بخش هر طراحی است. Entity مانند **چهره** یک مدار به دنیای خارج است مشخص می‌کند که مدار چه **ورودی‌هایی** دارد، چه **خروجی‌هایی** تولید می‌کند، و چه **پارامترهایی** قابل تنظیم هستند.

اگر یک مدار دیجیتال را به یک **جعبه سیاه (Black Box)** تشبیه کنیم، Entity همان **سطح بیرونی** جعبه است که نشان می‌دهد چه سیم‌هایی به آن وارد و چه سیم‌هایی از آن خارج می‌شوند.

---

## ۱. Entity چیست؟ تعریف جامع

ان تی تی**Entity** در VHDL، **رابط (Interface)** یک مدار با دنیای خارج را تعریف می‌کند. Entity مشخص می‌کند:
- **نام** مدار (نام ماژول)
- **پورت‌ها (Ports)** یا همان پایه‌های ورودی/خروجی
- **پارامترهای عمومی (Generics)** برای تنظیم رفتار مدار

### تشبیه ساده

یک Entity مانند **قاب یک نقاشی** است:
- قاب مشخص می‌کند نقاشی چه اندازه‌ای دارد (Generics)
- قاب مشخص می‌کند نقاشی از چه راه‌هایی با دنیای خارج ارتباط برقرار می‌کند (Ports)
- خود نقاشی (محتوای داخلی) در **Architecture** تعریف می‌شود

---

## ۲. ساختار Entity — تحلیل کامل

### فرمت کلی

```vhdl
entity <نام_موجودیت> is
    [generic (
        <نام_پارامتر> : <نوع> [:= <مقدار_پیش‌فرض>];
        ...
    );]
    port (
        <نام_پورت> : <جهت> <نوع> [:= <مقدار_پیش‌فرض>];
        ...
    );
end [entity] [<نام_موجودیت>];
```

### اجزای Entity

| بخش | توضیح | اجباری؟ |
|-----|-------|---------|
| **نام Entity** | نام منحصر‌به‌فرد برای ماژول | بله |
| **Generic** | پارامترهای قابل تنظیم | خیر |
| **Port** | ورودی‌ها و خروجی‌های مدار | بله |
| **End** | پایان Entity | بله |

---

## ۳. Port — درگاه‌های ورودی و خروجی

### تعریف Port

پورت **Port** مشخص می‌کند که مدار با دنیای خارج چگونه ارتباط برقرار می‌کند. هر Port دارای:
- **نام:** شناسه منحصر‌به‌فرد
- **جهت (Mode):** ورودی، خروجی، یا دوطرفه
- **نوع (Type):** نوع داده (std_logic, integer, و غیره)
- **مقدار پیش‌فرض (اختیاری):** مقدار اولیه

### جهات (Modes) در Port

| جهت | کلمه کلیدی | توضیح | مثال |
|-----|-----------|-------|------|
| **ورودی** | `in` | سیگنال وارد مدار می‌شود | سنسور، کلید، دکمه |
| **خروجی** | `out` | سیگنال از مدار خارج می‌شود | LED، موتور، نمایشگر |
| **دوطرفه** | `inout` | سیگنال هم وارد و هم خارج می‌شود | Bus داده |
| **بافر** | `buffer` | خروجی که در داخل مدار نیز قابل خواندن است | خروجی با بازخورد |

### نکات مهم درباره جهات

**۱. `in` (ورودی)**
- فقط قابل خواندن است (در داخل مدار)
- نمی‌توان به آن مقدار داد
- معمولاً برای سیگنال‌های خارجی

**۲. `out` (خروجی)**
- فقط قابل نوشتن است (در داخل مدار)
- نمی‌توان از آن در داخل مدار خواند (مگر با سیگنال میانی)
- معمولاً برای سیگنال‌های خروجی

**۳. `inout` (دوطرفه)**
- هم قابل خواندن و هم قابل نوشتن
- برای باس‌های داده که چندین دستگاه به آنها متصل می‌شوند
- نیاز به مدیریت دقیق‌تر دارد

**۴. `buffer` (بافر)**
- مانند `out` اما قابل خواندن در داخل مدار
- برای مواردی که خروجی به عنوان بازخورد استفاده می‌شود
- در طراحی‌های مدرن کمتر استفاده می‌شود (بهتر است از سیگنال میانی استفاده شود)

### مثال‌های Port

```vhdl
-- Entity با Portهای ساده
entity and_gate is
    port (
        a : in  std_logic;   -- ورودی ۱
        b : in  std_logic;   -- ورودی ۲
        y : out std_logic    -- خروجی
    );
end entity;

-- Entity با Portهای Vector (باس)
entity register_8bit is
    port (
        clk   : in  std_logic;
        reset : in  std_logic;
        en    : in  std_logic;
        d     : in  std_logic_vector(7 downto 0);
        q     : out std_logic_vector(7 downto 0)
    );
end entity;

-- Entity با Port دوطرفه
entity memory_interface is
    port (
        clk    : in  std_logic;
        addr   : in  std_logic_vector(15 downto 0);
        data   : inout std_logic_vector(7 downto 0);  -- دوطرفه
        wr_en  : in  std_logic;
        rd_en  : in  std_logic
    );
end entity;
```

## ۴. Generic — پارامترهای قابل تنظیم

### تعریف Generic

جنریس**Generic** به ما امکان می‌دهد که **پارامترهای عمومی** را به Entity اضافه کنیم تا ماژول قابل تنظیم (Configurable) و قابل استفاده مجدد (Reusable) باشد.

### مزایای Generic

1. **قابلیت استفاده مجدد:** یک ماژول با Genericهای مختلف قابل استفاده است
2. **انعطاف‌پذیری:** می‌توان عرض باس، عمق حافظه، و غیره را تنظیم کرد
3. **کاهش کد:** نیازی به نوشتن ماژول‌های جداگانه برای هر اندازه نیست
4. **مدیریت آسان:** تغییرات در یک نقطه اعمال می‌شود

### مثال‌های Generic

```vhdl
-- Generic برای عرض باس
entity register_generic is
    generic (
        WIDTH : positive := 8  -- عرض پیش‌فرض ۸ بیت
    );
    port (
        clk   : in  std_logic;
        reset : in  std_logic;
        d     : in  std_logic_vector(WIDTH-1 downto 0);
        q     : out std_logic_vector(WIDTH-1 downto 0)
    );
end entity;

-- Generic برای زمان‌بندی
entity counter_generic is
    generic (
        MAX_COUNT : integer := 255;
        WIDTH     : positive := 8
    );
    port (
        clk   : in  std_logic;
        reset : in  std_logic;
        q     : out std_logic_vector(WIDTH-1 downto 0);
        carry : out std_logic
    );
end entity;

-- Generic با مقدار پیش‌فرض و نوع سفارشی
entity fifo is
    generic (
        DEPTH : positive := 16;
        WIDTH : positive := 32;
        RAM_STYLE : string := "distributed"  -- نوع حافظه
    );
    port (
        clk      : in  std_logic;
        reset    : in  std_logic;
        wr_en    : in  std_logic;
        rd_en    : in  std_logic;
        wr_data  : in  std_logic_vector(WIDTH-1 downto 0);
        rd_data  : out std_logic_vector(WIDTH-1 downto 0);
        full     : out std_logic;
        empty    : out std_logic
    );
end entity;
```

### استفاده از Generic در Instantiation

```vhdl
-- Instantiation با Genericهای مشخص
uut: entity work.register_generic
    generic map (
        WIDTH => 16
    )
    port map (
        clk   => clk,
        reset => reset,
        d     => data_in,
        q     => data_out
    );
```

## ۵. نام‌گذاری Entity — بهترین شیوه‌ها

### اصول نام‌گذاری

۱. **معنی‌دار:** نام باید نشان‌دهنده عملکرد ماژول باشد
۲. **کوتاه اما گویا:** نه خیلی بلند، نه خیلی کوتاه
۳. **حروف کوچک:** معمولاً از حروف کوچک استفاده می‌شود
۴. **زیرخط:** برای جدا کردن کلمات از `_` استفاده می‌شود
۵. **بدون اعداد در ابتدا:** نام نباید با عدد شروع شود

### مثال‌های خوب

```vhdl
entity and_gate is ...
entity register_8bit is ...
entity counter_mod10 is ...
entity uart_transmitter is ...
entity cpu_control_unit is ...
entity fifo_buffer is ...
entity spi_master is ...
```

### مثال‌های بد

```vhdl
entity ag is ...              -- خیلی کوتاه، نامفهوم
entity my_module_1_2_3 is ... -- خیلی طولانی
entity 8bit_counter is ...    -- شروع با عدد (غیرمجاز)
entity something is ...       -- خیلی کلی، نامفهوم
```

## ۶. Entity و Architecture — رابطه و تفاوت

### رابطه

```
Entity (رابط خارجی)
    ↓
Architecture (محتوای داخلی)
```

Entity و Architecture با هم یک **ماژول کامل** را تشکیل می‌دهند.

### تفاوت‌ها

| ویژگی | Entity | Architecture |
|-------|--------|--------------|
| **نقش** | تعریف رابط خارجی | تعریف رفتار داخلی |
| **محتوای اصلی** | Portها و Genericها | کدهای VHDL (process, concurrent) |
| **تعداد** | یک Entity می‌تواند چندین Architecture داشته باشد | هر Architecture به یک Entity تعلق دارد |
| **قابل Synthesis** | بله | بله |

### مثال: یک Entity با دو Architecture

```vhdl
-- Entity (رابط)
entity and_gate is
    port (a, b : in std_logic; y : out std_logic);
end entity;

-- Architecture 1: رفتار
architecture behavioral of and_gate is
begin
    y <= a and b;
end architecture;

-- Architecture 2: ساختار (با گیت‌ها)
architecture structural of and_gate is
    signal a_n, b_n, y1, y2 : std_logic;
begin
    -- پیاده‌سازی با NAND
    a_n <= not a;
    b_n <= not b;
    y1 <= a_n nand b_n;
    y2 <= a nand b;
    y <= y1 and y2;
end architecture;
```

### انتخاب Architecture در Instantiation

```vhdl
uut: entity work.and_gate(behavioral)
    port map (a => a, b => b, y => y);
```

## ۷. Entity با Vectorها — تحلیل عمیق

### تعریف Vector در Port

```vhdl
-- Vector با اندیس نزولی (مرسوم‌تر)
data : in std_logic_vector(7 downto 0);

-- Vector با اندیس صعودی
data : in std_logic_vector(0 to 7);
```

### مثال‌های کامل

```vhdl
-- جمع‌کننده ۴ بیتی
entity adder_4bit is
    port (
        a     : in  std_logic_vector(3 downto 0);
        b     : in  std_logic_vector(3 downto 0);
        cin   : in  std_logic;
        sum   : out std_logic_vector(3 downto 0);
        cout  : out std_logic
    );
end entity;

-- مقایسه‌کننده ۸ بیتی
entity comparator_8bit is
    port (
        a     : in  std_logic_vector(7 downto 0);
        b     : in  std_logic_vector(7 downto 0);
        a_gt_b : out std_logic;
        a_eq_b : out std_logic;
        a_lt_b : out std_logic
    );
end entity;

-- حافظه با آدرس و داده
entity memory is
    generic (
        ADDR_WIDTH : positive := 8;
        DATA_WIDTH : positive := 16
    );
    port (
        clk     : in  std_logic;
        addr    : in  std_logic_vector(ADDR_WIDTH-1 downto 0);
        wr_data : in  std_logic_vector(DATA_WIDTH-1 downto 0);
        rd_data : out std_logic_vector(DATA_WIDTH-1 downto 0);
        wr_en   : in  std_logic;
        rd_en   : in  std_logic
    );
end entity;
```

## ۸. Entity با Generic و Port ترکیبی

### مثال کامل: FIFO با Generic

```vhdl
library ieee;
use ieee.std_logic_1164.all;

entity fifo_generic is
    generic (
        DEPTH : positive := 16;      -- عمق FIFO
        WIDTH : positive := 8;       -- عرض داده
        ALMOST_FULL_LEVEL : integer := 14;
        ALMOST_EMPTY_LEVEL : integer := 2
    );
    port (
        clk         : in  std_logic;
        reset       : in  std_logic;
        
        -- Write interface
        wr_en       : in  std_logic;
        wr_data     : in  std_logic_vector(WIDTH-1 downto 0);
        full        : out std_logic;
        almost_full : out std_logic;
        
        -- Read interface
        rd_en       : in  std_logic;
        rd_data     : out std_logic_vector(WIDTH-1 downto 0);
        empty       : out std_logic;
        almost_empty : out std_logic
    );
end entity;
```

## ۹. اشتباهات رایج در Entity

### اشتباه ۱: فراموش کردن `;` بین Portها

**نادرست:**
```vhdl
port (
    a : in std_logic
    b : in std_logic  -- ';' فراموش شده
    y : out std_logic
);
```

**درست:**
```vhdl
port (
    a : in std_logic;
    b : in std_logic;
    y : out std_logic
);
```

### اشتباه ۲: استفاده از جهت اشتباه

**نادرست:**
```vhdl
port (
    clk : out std_logic;  -- Clock باید in باشد
    led : in  std_logic   -- LED باید out باشد
);
```

**درست:**
```vhdl
port (
    clk : in  std_logic;
    led : out std_logic
);
```

### اشتباه ۳: فراموش کردن `end entity`

**نادرست:**
```vhdl
entity my_entity is
    port (
        a : in std_logic;
        b : out std_logic
    );
-- end missing
```

**درست:**
```vhdl
entity my_entity is
    port (
        a : in std_logic;
        b : out std_logic
    );
end entity;
```

### اشتباه ۴: نام‌های تکراری

**نادرست:**
```vhdl
port (
    data : in std_logic_vector(7 downto 0);
    data : out std_logic_vector(7 downto 0)  -- نام تکراری
);
```

**درست:**
```vhdl
port (
    data_in  : in  std_logic_vector(7 downto 0);
    data_out : out std_logic_vector(7 downto 0)
);
```

### اشتباه ۵: استفاده از `out` برای سیگنالی که در داخل خوانده می‌شود

**نادرست:**
```vhdl
port (
    q : out std_logic_vector(7 downto 0)
);
...
architecture rtl of ... is
begin
    -- نمی‌توان q را خواند (out است)
    process(clk)
    begin
        if q = x"FF" then  -- خطا: q را نمی‌توان خواند
            ...
        end if;
    end process;
end architecture;
```

**درست (استفاده از سیگنال میانی):**
```vhdl
port (
    q : out std_logic_vector(7 downto 0)
);
...
architecture rtl of ... is
    signal q_int : std_logic_vector(7 downto 0);
begin
    q <= q_int;  -- اتصال به خروجی
    
    process(clk)
    begin
        if q_int = x"FF" then  -- خواندن از سیگنال میانی
            ...
        end if;
    end process;
end architecture;
```

## ۱۱. تمرین‌های عملی

### تمرین ۱: طراحی Entity ساده

یک Entity برای **Half Adder** طراحی کنید که دارای دو ورودی `a` و `b` و دو خروجی `sum` و `carry` باشد.

**پاسخ:**
```vhdl
entity half_adder is
    port (
        a     : in  std_logic;
        b     : in  std_logic;
        sum   : out std_logic;
        carry : out std_logic
    );
end entity;
```

### تمرین ۲: Entity با Generic

یک Entity برای **Shift Register** طراحی کنید که با استفاده از Generic، عرض آن قابل تنظیم باشد.

**پاسخ:**
```vhdl
entity shift_register is
    generic (
        WIDTH : positive := 8
    );
    port (
        clk : in  std_logic;
        si  : in  std_logic;
        q   : out std_logic_vector(WIDTH-1 downto 0)
    );
end entity;
```

### تمرین ۳: Entity کامل

یک Entity برای **Counter Modulo-N** طراحی کنید که:
- عرض قابل تنظیم داشته باشد
- مقدار ماکزیمم قابل تنظیم داشته باشد
- ورودی‌های clk, reset, enable داشته باشد
- خروجی count و carry داشته باشد

**پاسخ:**
```vhdl
entity counter_mod_n is
    generic (
        WIDTH : positive := 8;
        MAX   : positive := 255
    );
    port (
        clk   : in  std_logic;
        reset : in  std_logic;
        en    : in  std_logic;
        count : out std_logic_vector(WIDTH-1 downto 0);
        carry : out std_logic
    );
end entity;
```

## ۱۲. خلاصه و جمع‌بندی

### نکات کلیدی

| مفهوم | توضیح |
|-------|-------|
| **Entity** | رابط خارجی مدار را تعریف می‌کند |
| **Port** | ورودی‌ها و خروجی‌های مدار را مشخص می‌کند |
| **Mode** | جهت پورت: `in`, `out`, `inout`, `buffer` |
| **Generic** | پارامترهای قابل تنظیم برای انعطاف‌پذیری |
| **Name** | نام Entity باید معنی‌دار و منحصر‌به‌فرد باشد |
| **Architecture** | محتوای داخلی مدار را توصیف می‌کند |

### فرمت کامل Entity

```vhdl
entity <name> is
    generic (
        <param> : <type> := <default>
    );
    port (
        <signal> : <mode> <type> := <default>
    );
end entity <name>;
```

### پیام نهایی

Entity **درگاه ورود** به هر طراحی VHDL است. درک کامل Entity، پایه‌ای محکم برای طراحی ماژول‌های قابل استفاده مجدد، خوانا، و حرفه‌ای ایجاد می‌کند. با تسلط بر Entity، شما می‌توانید:
- ماژول‌های قابل تنظیم (Generic) طراحی کنید
- رابط‌های واضح و مستند ایجاد کنید
- طراحی‌های پیچیده را به ماژول‌های کوچک‌تر تقسیم کنید
- کدهای قابل استفاده مجدد بنویسید
