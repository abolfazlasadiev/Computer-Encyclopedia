# Architecture در VHDL — تحلیل جامع و عمیق

## مقدمه: قلب تپنده طراحی

اگر **Entity** مانند **چهره** یک مدار به دنیای خارج است، **Architecture** مانند **بدن** و **روح** آن مدار است — جایی که **رفتار واقعی** سخت‌افزار توصیف می‌شود. Architecture مشخص می‌کند که مدار **چه کاری انجام می‌دهد** و **چگونه** ورودی‌ها را به خروجی‌ها تبدیل می‌کند.

در VHDL، یک Entity می‌تواند چندین Architecture داشته باشد که هر کدام پیاده‌سازی متفاوتی از همان رابط را ارائه می‌دهند. این ویژگی به طراح اجازه می‌دهد تا:
- **نسخه‌های مختلف** از یک ماژول را ایجاد کند
- **بهینه‌سازی‌های مختلف** را بررسی کند
- **ساختار (Structural)** و **رفتار (Behavioral)** را با هم مقایسه کند

---

## ۱. Architecture چیست؟ تعریف جامع

**Architecture** در VHDL، بخشی است که **رفتار داخلی** یا **ساختار** یک مدار را توصیف می‌کند. Architecture مشخص می‌کند که چگونه سیگنال‌های ورودی به سیگنال‌های خروجی تبدیل می‌شوند.

### تشبیه ساده

اگر Entity مانند **قاب یک نقاشی** باشد، Architecture مانند **خود نقاشی** است:
- قاب (Entity) مشخص می‌کند نقاشی چه اندازه‌ای دارد و چگونه آویزان می‌شود
- نقاشی (Architecture) مشخص می‌کند چه چیزی روی بوم کشیده شده است

---

## ۲. ساختار Architecture — تحلیل کامل

### فرمت کلی

```vhdl
architecture <نام_معماری> of <نام_موجودیت> is
    -- بخش اعلان (Declarative Part)
    -- سیگنال‌های داخلی
    -- ثابت‌ها
    -- نوع‌ها
    -- Componentها
    -- توابع/رویه‌ها
begin
    -- بخش بدنه (Concurrent Statements)
    -- انتساب‌های همزمان (Concurrent Assignments)
    -- Processها
    -- Component Instantiationها
    -- Generate statements
end architecture [<نام_معماری>];
```

### اجزای Architecture

| بخش | توضیح | اجباری؟ |
|-----|-------|---------|
| **نام Architecture** | نام منحصر‌به‌فرد برای این پیاده‌سازی | بله |
| **نام Entity** | نام Entity که این Architecture به آن تعلق دارد | بله |
| **Declarative Part** | اعلان سیگنال‌ها، ثابت‌ها، نوع‌ها، Componentها | خیر |
| **Concurrent Statements** | کدهای توصیف‌کننده رفتار یا ساختار | بله |
| **End** | پایان Architecture | بله |

## ۳. انواع Architecture — سه رویکرد اصلی

در VHDL، سه رویکرد اصلی برای توصیف Architecture وجود دارد:

### ۱. Behavioral (رفتاری)

**توصیف:** مدار را بر اساس **رفتار** و **رابطه ورودی-خروجی** توصیف می‌کند، بدون اینکه مشخص کند چگونه پیاده‌سازی شده است.

```vhdl
architecture behavioral of half_adder is
begin
    sum   <= a xor b;
    carry <= a and b;
end architecture;
```

**مزایا:** ساده، خوانا، مستقل از فناوری
**معایب:** ممکن است بهینه‌ترین نباشد

---

### ۲. Structural (ساختاری)

**توصیف:** مدار را به عنوان **اتصال** Componentهای کوچک‌تر توصیف می‌کند.

```vhdl
architecture structural of full_adder is
    component half_adder
        port (a, b : in std_logic; sum, carry : out std_logic);
    end component;
    component or_gate
        port (a, b : in std_logic; y : out std_logic);
    end component;
    
    signal s1, c1, c2 : std_logic;
begin
    ha1: half_adder port map (a => a, b => b, sum => s1, carry => c1);
    ha2: half_adder port map (a => s1, b => cin, sum => sum, carry => c2);
    or1: or_gate port map (a => c1, b => c2, y => cout);
end architecture;
```

**مزایا:** شبیه به طراحی مدار واقعی، قابل استفاده مجدد
**معایب:** پیچیده‌تر، وابسته به Componentها

---

### ۳. Dataflow (جریان داده)

**توصیف:** مدار را با استفاده از **انتساب‌های همزمان** و **عبارات منطقی** توصیف می‌کند (بین Behavioral و Structural).

```vhdl
architecture dataflow of full_adder is
    signal s1, c1, c2 : std_logic;
begin
    s1   <= a xor b;
    c1   <= a and b;
    c2   <= s1 and cin;
    sum  <= s1 xor cin;
    cout <= c1 or c2;
end architecture;
```

**مزایا:** تعادل بین خوانایی و جزئیات
**معایب:** ممکن است برای مدارهای پیچیده مناسب نباشد

---

## ۴. Declarative Part — اعلان‌ها در Architecture

### ۴.۱. Signal — سیگنال‌های داخلی

سیگنال‌های داخلی برای اتصال بخش‌های مختلف مدار استفاده می‌شوند.

```vhdl
architecture rtl of my_circuit is
    signal temp : std_logic;
    signal data_bus : std_logic_vector(7 downto 0);
    signal counter : integer range 0 to 255;
begin
    -- استفاده از سیگنال‌ها
    temp <= a and b;
    data_bus <= temp & "0000000";
end architecture;
```

### ۴.۲. Constant — ثابت‌ها

ثابت‌ها برای مقادیری که تغییر نمی‌کنند استفاده می‌شوند.

```vhdl
architecture rtl of my_circuit is
    constant CLK_PERIOD : time := 10 ns;
    constant DATA_WIDTH : integer := 8;
    constant MAX_COUNT : integer := 255;
begin
    -- استفاده از ثابت‌ها
    process(clk)
        variable count : integer range 0 to MAX_COUNT;
    begin
        ...
    end process;
end architecture;
```

### ۴.۳. Type — نوع‌های سفارشی

نوع‌های سفارشی برای ساختاردهی بهتر داده‌ها استفاده می‌شوند.

```vhdl
architecture rtl of fsm is
    type state_type is (IDLE, RUN, DONE);
    signal state, next_state : state_type;
begin
    ...
end architecture;
```

### ۴.۴. Component — مؤلفه‌ها

Componentها برای استفاده از ماژول‌های دیگر در Architecture ساختاری استفاده می‌شوند.

```vhdl
architecture structural of top_module is
    component and_gate
        port (a, b : in std_logic; y : out std_logic);
    end component;
    
    component or_gate
        port (a, b : in std_logic; y : out std_logic);
    end component;
begin
    u1: and_gate port map (a => a, b => b, y => s1);
    u2: or_gate port map (a => s1, b => c, y => y);
end architecture;
```

## ۵. Concurrent Statements — دستورات همزمان

در VHDL، همه دستورات در Architecture **همزمان (Concurrent)** اجرا می‌شوند، مگر اینکه داخل Process باشند.

### ۵.۱. Concurrent Signal Assignment

```vhdl
-- ساده‌ترین شکل
y <= a and b;

-- با شرط (Conditional)
y <= a when sel = '0' else b;

-- با انتخاب (Selected)
with sel select
    y <= a when "00",
         b when "01",
         c when "10",
         d when "11";
```

### ۵.۲. Process

```vhdl
process(clk, reset)
begin
    if reset = '1' then
        q <= '0';
    elsif rising_edge(clk) then
        q <= d;
    end if;
end process;
```

### ۵.۳. Component Instantiation

```vhdl
u1: entity work.and_gate(behavioral)
    port map (
        a => a_signal,
        b => b_signal,
        y => y_signal
    );
```

### ۵.۴. Generate

```vhdl
gen: for i in 0 to 7 generate
    bit_reg: entity work.dff
        port map (
            clk => clk,
            d   => data_in(i),
            q   => data_out(i)
        );
end generate;
```

## ۶. Signal در مقابل Variable — تفاوت اساسی

### Signal (سیگنال)

```vhdl
architecture rtl of example is
    signal s : integer := 0;
begin
    process(clk)
    begin
        if rising_edge(clk) then
            s <= s + 1;  -- به‌روزرسانی در پایان Process
        end if;
    end process;
end architecture;
```

**ویژگی‌ها:**
- مقدار در **پایان** Process به‌روز می‌شود
- دارای **حافظه** (در سخت‌افزار به Register تبدیل می‌شود)
- برای ارتباط بین Processها استفاده می‌شود

### Variable (متغیر)

```vhdl
architecture rtl of example is
begin
    process(clk)
        variable v : integer := 0;
    begin
        if rising_edge(clk) then
            v := v + 1;  -- به‌روزرسانی فوری
        end if;
    end process;
end architecture;
```

**ویژگی‌ها:**
- مقدار **فوراً** به‌روز می‌شود
- **بدون حافظه** (در سخت‌افزار به Wire تبدیل می‌شود)
- فقط در همان Process قابل استفاده است

### مقایسه

| ویژگی | Signal | Variable |
|-------|--------|----------|
| **به‌روزرسانی** | پایان Process | فوری |
| **حافظه** | دارد (Register) | ندارد (Wire) |
| **حوزه** | کل Architecture | فقط همان Process |
| **سخت‌افزار** | Flip-Flop یا Wire | معمولاً Wire |
| **انتساب** | `<=` | `:=` |

## ۷. Process — قلب منطق ترتیبی

### ساختار Process

```vhdl
[label:] process (sensitivity_list) [is]
    [declarative_part]
begin
    -- Sequential statements
end process [label];
```

### انواع Process

**۱. Process با Clock (Sequential):**
```vhdl
process(clk, reset)
begin
    if reset = '1' then
        q <= '0';
    elsif rising_edge(clk) then
        q <= d;
    end if;
end process;
```

**۲. Process ترکیبی (Combinational):**
```vhdl
process(a, b, sel)
begin
    if sel = '0' then
        y <= a;
    else
        y <= b;
    end if;
end process;
```

**۳. Process با `all` (VHDL-2008):**
```vhdl
process(all)
begin
    y <= a and b;
end process;
```

## ۸. Component Instantiation — استفاده از ماژول‌ها

### روش ۱: با Component Declaration

```vhdl
architecture structural of top is
    component and_gate
        port (a, b : in std_logic; y : out std_logic);
    end component;
begin
    u1: and_gate port map (a => sig_a, b => sig_b, y => sig_y);
end architecture;
```

### روش ۲: Direct Entity Instantiation (VHDL-93)

```vhdl
architecture structural of top is
begin
    u1: entity work.and_gate(behavioral)
        port map (
            a => sig_a,
            b => sig_b,
            y => sig_y
        );
end architecture;
```

### روش ۳: Positional Mapping

```vhdl
u1: and_gate port map (sig_a, sig_b, sig_y);
```

**توصیه:** از **Named Mapping** استفاده کنید (خوانایی بهتر).

## ۹. Generate — تولید کدهای تکراری

### For-Generate

```vhdl
gen: for i in 0 to 7 generate
    reg_i: entity work.dff
        port map (
            clk => clk,
            d   => data_in(i),
            q   => data_out(i)
        );
end generate;
```

### If-Generate

```vhdl
gen: if WIDTH = 8 generate
    -- مدار ۸ بیتی
end generate;

gen: if WIDTH = 16 generate
    -- مدار ۱۶ بیتی
end generate;
```

### Case-Generate (VHDL-2008)

```vhdl
gen: case WIDTH generate
    when 8 =>
        -- مدار ۸ بیتی
    when 16 =>
        -- مدار ۱۶ بیتی
    when others =>
        -- مدار پیش‌فرض
end generate;
```

## ۱۰. معماری‌های مختلف برای یک Entity — مقایسه

### یک Entity با سه Architecture

```vhdl
-- ===== Entity =====
entity counter is
    port (clk, reset : in std_logic; q : out integer range 0 to 15);
end entity;

-- ===== Architecture 1: Behavioral =====
architecture behavioral of counter is
    signal count : integer range 0 to 15;
begin
    process(clk, reset)
    begin
        if reset = '1' then
            count <= 0;
        elsif rising_edge(clk) then
            count <= count + 1;
        end if;
    end process;
    q <= count;
end architecture;

-- ===== Architecture 2: Dataflow =====
architecture dataflow of counter is
    signal count : integer range 0 to 15;
begin
    count <= 0 when reset = '1' else
             (count + 1) mod 16 when rising_edge(clk);
    q <= count;
end architecture;

-- ===== Architecture 3: Structural =====
architecture structural of counter is
    -- با استفاده از Flip-Flopهای مجزا
    component dff
        port (clk, reset, d : in std_logic; q : out std_logic);
    end component;
    -- ... اتصالات
begin
    -- ...
end architecture;
```

### انتخاب Architecture در Instantiation

```vhdl
u1: entity work.counter(behavioral) port map (...);
u2: entity work.counter(dataflow) port map (...);
u3: entity work.counter(structural) port map (...);
```

## ۱۱. اشتباهات رایج در Architecture

### اشتباه ۱: فراموش کردن Sensitivity List

**نادرست:**
```vhdl
process(a, b)  -- c در لیست نیست
begin
    y <= a and b and c;
end process;
```

**درست:**
```vhdl
process(a, b, c)
begin
    y <= a and b and c;
end process;
```

### اشتباه ۲: ایجاد Latch ناخواسته

**نادرست:**
```vhdl
process(a, b)
begin
    if sel = '1' then
        y <= a;
    end if;
    -- وقتی sel=0، y مقدار جدیدی نمی‌گیرد → Latch
end process;
```

**درست:**
```vhdl
process(a, b, sel)
begin
    if sel = '1' then
        y <= a;
    else
        y <= b;
    end if;
end process;
```

### اشتباه ۳: استفاده از Signal به جای Variable

**نادرست (زمانی که نیاز به مقدار فوری داریم):**
```vhdl
process(clk)
    signal temp : integer;  -- Signal
begin
    if rising_edge(clk) then
        temp <= temp + 1;
        y <= temp;  -- مقدار قدیمی temp را می‌گیرد!
    end if;
end process;
```

**درست:**
```vhdl
process(clk)
    variable temp : integer;  -- Variable
begin
    if rising_edge(clk) then
        temp := temp + 1;
        y <= temp;  -- مقدار جدید temp را می‌گیرد
    end if;
end process;
```

### اشتباه ۴: Driver Multiple

**نادرست:**
```vhdl
architecture rtl of my_circuit is
begin
    y <= a and b;  -- این
    y <= c or d;   -- و این هر دو به y مقدار می‌دهند → خطا
end architecture;
```

**درست:** فقط یک Driver برای هر Signal.

## ۱۲. تمرین‌های عملی

### تمرین ۱: Architecture Behavioral

برای Entity زیر یک Architecture Behavioral بنویسید:

```vhdl
entity mux2 is
    port (a, b, sel : in std_logic; y : out std_logic);
end entity;
```

**پاسخ:**
```vhdl
architecture behavioral of mux2 is
begin
    y <= a when sel = '0' else b;
end architecture;
```

### تمرین ۲: Architecture Structural

با استفاده از AND و OR Gate، یک 2:1 MUX بسازید.

**پاسخ:**
```vhdl
architecture structural of mux2 is
    component and_gate
        port (a, b : in std_logic; y : out std_logic);
    end component;
    component or_gate
        port (a, b : in std_logic; y : out std_logic);
    end component;
    component not_gate
        port (a : in std_logic; y : out std_logic);
    end component;
    
    signal sel_n, a_and, b_and : std_logic;
begin
    u1: not_gate port map (sel, sel_n);
    u2: and_gate port map (a, sel_n, a_and);
    u3: and_gate port map (b, sel, b_and);
    u4: or_gate port map (a_and, b_and, y);
end architecture;
```

### تمرین ۳: Architecture با Process

یک D Flip-Flop با Enable و Reset همزمان بنویسید.

**پاسخ:**
```vhdl
architecture rtl of dff is
begin
    process(clk)
    begin
        if rising_edge(clk) then
            if reset = '1' then
                q <= '0';
            elsif en = '1' then
                q <= d;
            end if;
        end if;
    end process;
end architecture;
```

## ۱۳. خلاصه و جمع‌بندی

### نکات کلیدی

| مفهوم | توضیح |
|-------|-------|
| **Architecture** | رفتار داخلی مدار را توصیف می‌کند |
| **Behavioral** | توصیف مبتنی بر رفتار |
| **Structural** | توصیف مبتنی بر اتصال Componentها |
| **Dataflow** | توصیف مبتنی بر جریان داده |
| **Signal** | سیگنال داخلی (به‌روزرسانی در پایان Process) |
| **Variable** | متغیر داخلی (به‌روزرسانی فوری) |
| **Process** | بلوک دستورات ترتیبی |
| **Generate** | تولید کدهای تکراری |

### فرمت کامل Architecture

```vhdl
architecture <name> of <entity> is
    -- Declarations
    signal <signal_name> : <type> := <initial>;
    constant <const_name> : <type> := <value>;
    type <type_name> is <type_definition>;
    component <component_name> is ...
begin
    -- Concurrent Statements
    -- Signal assignments
    -- Process blocks
    -- Component instantiations
    -- Generate statements
end architecture <name>;
```

### پیام نهایی

Architecture **قلب** هر طراحی VHDL است. انتخاب نوع Architecture (Behavioral، Structural، یا Dataflow) به نیاز طراحی و سبک شما بستگی دارد. با تسلط بر Architecture، شما می‌توانید:
- مدارهای پیچیده را به روش‌های مختلف پیاده‌سازی کنید
- از Componentهای موجود استفاده مجدد کنید
- کدهای بهینه و خوانا بنویسید
- طراحی‌های خود را مستند کنید

> **به یاد داشته باشید:** در VHDL، ما برنامه نمی‌نویسیم — ما **سخت‌افزار را توصیف می‌کنیم**. Architecture جایی است که این توصیف اتفاق می‌افتد.
