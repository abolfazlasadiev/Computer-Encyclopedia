# Multiplexers — مالتی‌پلکسرها

**Multiplexer یا MUX** یکی از مهم‌ترین مدارهای **Combinational Logic** است.

اگر بخواهیم خیلی ساده تعریف کنیم:

> **MUX از بین چند ورودی، یکی را انتخاب می‌کند و آن را به خروجی می‌فرستد.**

به همین دلیل معمولاً به آن می‌گویند:

> **Data Selector**

مسیر مفهومی:

```text
Logic Gates
    ↓
Multiplexer
    ↓
Data Selection
    ↓
ALU / Datapath
    ↓
CPU
```

و در مسیر VHDL:

```text
if / case
   ↓
MUX
   ↓
Combinational RTL
```

---

# 1. ایده اصلی Multiplexer

فرض کنیم دو ورودی داریم:

```text
A
B
```

و می‌خواهیم فقط یکی از آنها به خروجی برود.

یک ورودی انتخاب داریم:

```text
S
```

ساختار:

```text
        ┌─────────────┐
A ─────→│             │
B ─────→│    2:1 MUX  │────→ Y
S ─────→│             │
        └─────────────┘
```

اگر:

```text
S = 0
```

باشد:

```text
Y = A
```

و اگر:

```text
S = 1
```

باشد:

```text
Y = B
```

پس:

```text
Y = A when S=0
Y = B when S=1
```

---

# 2. Truth Table — 2:1 MUX

|S|Y|
|--:|---|
|0|A|
|1|B|

یا اگر ورودی‌ها را هم بنویسیم:

|S|A|B|Y|
|--:|--:|--:|---|
|0|0|X|0|
|0|1|X|1|
|1|X|0|0|
|1|X|1|1|

`X` یعنی مقدار آن ورودی در انتخاب فعلی اهمیتی ندارد.

---

# 3. معادله Boolean

یک 2:1 MUX را می‌توان با Boolean Algebra نوشت:

```text
Y = (A AND NOT S) OR (B AND S)
```

یا:

```text
Y = A·S̅ + B·S
```

منطق آن:

```text
S = 0
    ↓
A فعال می‌شود

S = 1
    ↓
B فعال می‌شود
```

---

# 4. MUX از Logic Gates

یک 2:1 MUX را می‌توان با:

```text
NOT
AND
OR
```

ساخت.

```text
             ┌─────┐
S ──────────→│ NOT │───→ S̅
             └─────┘
                │
A ──────────────┼──→ AND ──┐
                │          │
                └──────────┤
                           OR ───→ Y
B ─────────────────→ AND ──┘
                     ↑
                     S
```

پس دانشجو باید بفهمد که MUX یک قطعه جادویی نیست؛ در نهایت از Logic Gates ساخته شده است.

---

# 5. چرا MUX مهم است؟

MUX یکی از پایه‌های اصلی **Data Path** است.

مثلاً فرض کنیم ALU دو ورودی دارد:

```text
        ┌─────────┐
A ─────→│         │
B ─────→│   ALU   │────→ Result
        │         │
        └─────────┘
```

حالا اگر بخواهیم انتخاب کنیم ALU از کدام داده استفاده کند:

```text
Register 1 ──┐
             ├──→ MUX ──→ ALU
Register 2 ──┘
```

در CPU تعداد زیادی MUX برای انتخاب مسیر داده استفاده می‌شود.

---

# 6. 4:1 Multiplexer

حالا چهار ورودی داریم:

```text
D0
D1
D2
D3
```

و دو بیت Select:

```text
S1
S0
```

ساختار:

```text
D0 ─────┐
D1 ─────┤
D2 ─────┤──→ 4:1 MUX ───→ Y
D3 ─────┤
S1 ─────┤
S0 ─────┘
```

چرا دو Select لازم داریم؟

چون:

```text
2² = 4
```

دو بیت می‌توانند چهار حالت ایجاد کنند:

```text
00
01
10
11
```

---

# 7. Truth Table — 4:1 MUX

|S1|S0|Output|
|--:|--:|---|
|0|0|D0|
|0|1|D1|
|1|0|D2|
|1|1|D3|

پس:

```text
S1 S0
─────
00 → D0
01 → D1
10 → D2
11 → D3
```

---

# 8. قانون عمومی MUX

اگر تعداد ورودی‌ها:

```text
N
```

باشد، تعداد Select Lineها:

```text
log₂(N)
```

است.

مثلاً:

|MUX|Data Inputs|Select Lines|
|---|--:|--:|
|2:1|2|1|
|4:1|4|2|
|8:1|8|3|
|16:1|16|4|
|32:1|32|5|

فرمول:

```text
Number of Inputs = 2^Number of Select Lines
```

---

# 9. 4:1 MUX با Boolean Logic

برای 4:1 MUX می‌توانیم بنویسیم:

```text
Y =
D0·S̅1·S̅0
+
D1·S̅1·S0
+
D2·S1·S̅0
+
D3·S1·S0
```

اما در VHDL معمولاً لازم نیست این معادله طولانی را مستقیماً بنویسیم.

می‌توانیم از `case` استفاده کنیم.

---

# 10. 2:1 MUX در VHDL

ساده‌ترین روش:

```vhdl
library ieee;
use ieee.std_logic_1164.all;

entity mux2 is
    port (
        a : in  std_logic;
        b : in  std_logic;
        s : in  std_logic;
        y : out std_logic
    );
end entity;

architecture rtl of mux2 is
begin

    y <= a when s = '0' else b;

end architecture;
```

این یک **Concurrent Conditional Assignment** است.

و از نظر سخت‌افزاری یعنی:

```text
A ──┐
    ├── MUX ──→ Y
B ──┘
     ↑
     S
```

---

# 11. 4:1 MUX با `case`

برای MUX بزرگ‌تر، `case` بسیار خوانا است:

```vhdl
library ieee;
use ieee.std_logic_1164.all;

entity mux4 is
    port (
        d0 : in  std_logic;
        d1 : in  std_logic;
        d2 : in  std_logic;
        d3 : in  std_logic;

        s  : in  std_logic_vector(1 downto 0);

        y  : out std_logic
    );
end entity;

architecture rtl of mux4 is
begin

    process(all)
    begin
        case s is
            when "00" =>
                y <= d0;

            when "01" =>
                y <= d1;

            when "10" =>
                y <= d2;

            when "11" =>
                y <= d3;

            when others =>
                y <= '0';
        end case;
    end process;

end architecture;
```

نکته مهم این است که MUX **Combinational** است؛ بنابراین Clock ندارد.

---

# 12. چرا `process(all)`؟

در VHDL مدرن می‌توانیم برای یک Process ترکیبی بنویسیم:

```vhdl
process(all)
```

یعنی process به تمام Signalهایی که داخل آن استفاده شده‌اند حساس باشد.

این کار احتمال اشتباه در Sensitivity List را کاهش می‌دهد.

در کدهای قدیمی‌تر ممکن است ببینی:

```vhdl
process(a, b, s)
```

هر دو مفهوم را دانشجو باید بشناسد، ولی برای VHDL مدرن، `process(all)` بسیار مناسب است.

---

# 13. MUX و `if`

یک 2:1 MUX را می‌توان با `if` نیز نوشت:

```vhdl
process(all)
begin
    if s = '0' then
        y <= a;
    else
        y <= b;
    end if;
end process;
```

پس:

```text
if
 ↓
Combinational Selection
 ↓
MUX
```

این یکی از مهم‌ترین ارتباط‌هایی است که باید در دانشنامه برجسته شود.

---

# 14. MUX با Vector

MUX فقط برای یک بیت نیست.

مثلاً می‌توانیم دو Bus هشت‌بیتی داشته باشیم:

```text
A = 10101010
B = 11001100
```

و:

```text
S = 0
```

آنگاه:

```text
Y = A
  = 10101010
```

اگر:

```text
S = 1
```

باشد:

```text
Y = B
  = 11001100
```

در VHDL:

```vhdl
entity mux2_8bit is
    port (
        a : in  std_logic_vector(7 downto 0);
        b : in  std_logic_vector(7 downto 0);
        s : in std_logic;
        y : out std_logic_vector(7 downto 0)
    );
end entity;

architecture rtl of mux2_8bit is
begin
    y <= a when s = '0' else b;
end architecture;
```

اینجا در واقع:

```text
8 × 1-bit MUX
```

را می‌توان به‌صورت مفهومی یک **8-bit 2:1 MUX** در نظر گرفت.

---

# 15. MUX به صورت Hierarchical

می‌توان MUXهای کوچک‌تر را برای ساخت MUX بزرگ‌تر استفاده کرد.

مثلاً یک 4:1 MUX را می‌توان با سه 2:1 MUX ساخت:

```text
D0 ──┐
     ├── MUX ──┐
D1 ──┘         │
               ├── MUX ──→ Y
D2 ──┐         │
     ├── MUX ──┘
D3 ──┘
```

پس:

```text
3 × 2:1 MUX
       ↓
    4:1 MUX
```

این ایده برای آموزش **Hierarchical Design** بسیار خوب است.

---

# 16. MUX Tree

برای تعداد زیادی ورودی می‌توان یک ساختار درختی ساخت:

```text
D0 ─┐
    ├─MUX─┐
D1 ─┘     │
          ├─MUX─┐
D2 ─┐     │     │
    ├─MUX─┘     │
D3 ─┘           ├─MUX → Y
                │
D4 ─┐           │
    ├─MUX─┐     │
D5 ─┘     │     │
          ├─MUX─┘
D6 ─┐     │
    ├─MUX─┘
D7 ─┘
```

این ساختار به دانشجو نشان می‌دهد که یک مدار بزرگ می‌تواند از بلوک‌های کوچک‌تر ساخته شود.

---

# 17. MUX در ALU

یکی از مهم‌ترین کاربردهای MUX در **ALU** است.

فرض کنیم ALU می‌تواند:

```text
ADD
SUB
AND
OR
```

انجام دهد.

نتایج مختلف تولید می‌شوند:

```text
        ┌── ADD ──┐
A,B ───→│         │
        ├── SUB ──┤
        ├── AND ──┤
        └── OR ───┘
              ↓
             MUX
              ↓
           Result
```

Signal انتخاب تعیین می‌کند کدام نتیجه به خروجی ALU برود.

پس MUX بخش مهمی از **Data Selection** در ALU است.

---

# 18. MUX در CPU

در CPU نیز MUXها دائماً بین مسیرهای مختلف داده انتخاب می‌کنند.

مثلاً:

```text
             ┌──────────┐
Register A ─→│          │
             │   MUX    │──→ ALU
Register B ─→│          │
             └──────────┘
                  ↑
                Select
```

یا:

```text
             ┌──────────┐
PC ─────────→│          │
Register ───→│   MUX    │──→ Address
             │          │
             └──────────┘
```

در یک CPU واقعی MUXها در بخش‌های مختلف Datapath حضور دارند.

---

# 19. MUX در مقابل DEMUX

این دو را نباید با هم اشتباه کرد.

### Multiplexer

چند ورودی:

```text
Many → One
```

```text
D0 ─┐
D1 ─┤
D2 ─┼──→ MUX ──→ Y
D3 ─┘
```

---

### Demultiplexer

یک ورودی:

```text
One → Many
```

```text
             ┌──→ Y0
             │
D ──→ DEMUX ─┼──→ Y1
             │
             ├──→ Y2
             │
             └──→ Y3
```

پس:

```text
MUX
Many → One

DEMUX
One → Many
```

---

# 20. MUX در مقابل Decoder

این دو هم متفاوت‌اند.

### Decoder

یک کد را به یک خروجی فعال تبدیل می‌کند:

```text
2-bit Input
    ↓
Decoder
    ↓
4 Outputs
```

مثلاً:

```text
00 → 0001
01 → 0010
10 → 0100
11 → 1000
```

### MUX

از چند داده، یک داده را انتخاب می‌کند:

```text
D0
D1
D2
D3
 ↓
MUX
 ↓
Y
```

پس:

```text
Decoder → انتخاب/فعال‌سازی خروجی‌ها
MUX     → انتخاب داده
```

البته در سطح سخت‌افزاری این دو می‌توانند در ساختارهای پیچیده‌تر با هم ترکیب شوند.

---

# 21. MUX و Tri-State

در سیستم‌های قدیمی‌تر یا برخی Bus Architectureها ممکن است برای اشتراک Bus از Tri-State استفاده شود:

```text
Device A ──┐
Device B ──┼──→ BUS
Device C ──┘
```

اما در FPGAهای مدرن، برای منطق داخلی معمولاً استفاده از **MUX** و Routing داخلی ترجیح داده می‌شود و Tri-State عمدتاً در I/Oها مطرح است.

برای دانشنامه بهتر است این موضوع را در بخش Advanced/FPGA مطرح کنی، نه در آموزش مقدماتی MUX.

---

# 22. MUX و Combinational Logic

MUX خودش یک مدار ترکیبی است.

بنابراین:

```text
No Clock
No Memory
No State
```

دارد.

خروجی فقط تابع ورودی‌ها و Select است:

```text
Y = f(D, S)
```

این را در مقابل Counter قرار بده:

```text
MUX:
Y = f(Current Inputs)

Counter:
Next State = f(Current State)
```

این مقایسه برای درک تفاوت **Combinational** و **Sequential** بسیار مفید است.

---

# 23. اشتباه مهم در VHDL: Incomplete Assignment

در یک Combinational Process باید خروجی برای تمام حالت‌ها مقدار بگیرد.

مثلاً این کد:

```vhdl
process(all)
begin
    if s = '1' then
        y <= b;
    end if;
end process;
```

مشکل دارد.

وقتی:

```text
s = 0
```

است، `y` مقدار جدیدی دریافت نمی‌کند.

این می‌تواند باعث ایجاد **Latch** شود.

برای MUX باید حالت دیگر را هم مشخص کنیم:

```vhdl
process(all)
begin
    if s = '1' then
        y <= b;
    else
        y <= a;
    end if;
end process;
```

این نکته را حتماً در دانشنامه قرار بده:

> **Combinational Logic باید برای تمام مسیرهای منطقی خروجی تعیین کند.**

---

# 24. MUX و `when ... else`

یکی از زیباترین روش‌های توصیف MUX در VHDL:

```vhdl
y <= a when s = '0' else b;
```

این کد از نظر مفهومی تقریباً مستقیماً به MUX ترجمه می‌شود:

```text
             S
             ↓
A ────────→ MUX ─────→ Y
B ────────→
```

بنابراین برای پروژه‌های ساده، این روش بسیار خوانا است.

# 30. چیزی که دانشجو باید در پایان این بخش بداند

دانشجو نباید فقط بداند:

> `when ... else` برای MUX استفاده می‌شود.

باید این زنجیره را بفهمد:

```text
Problem
   ↓
"از بین چند داده، یکی را انتخاب کن"
   ↓
MUX
   ↓
Truth Table
   ↓
Boolean Equation
   ↓
Logic Gates
   ↓
VHDL
   ↓
Simulation
   ↓
Synthesis
   ↓
Hardware
```

و مهم‌تر:

```text
2:1 MUX
   ↓
4:1 MUX
   ↓
8:1 MUX
   ↓
Bus MUX
   ↓
ALU MUX
   ↓
Datapath
   ↓
CPU
```

بنابراین **Multiplexer** فقط یک مبحث کوچک از Combinational Logic نیست؛ یکی از بلوک‌های اصلی برای فهمیدن این است که چگونه **داده در یک سیستم دیجیتال از یک مسیر به مسیر دیگر هدایت و انتخاب می‌شود**.

گام بعدی مناسب در همین بخش **Decoders** است؛ چون مقایسه‌ی مستقیم `MUX vs Decoder` به دانشجو کمک می‌کند تفاوت «انتخاب داده» و «انتخاب/فعال‌سازی خروجی» را دقیق بفهمد.
