# جدول درستی (Truth Tables) — نسخه کامل و جامع

## مقدمه: نقشه راه طراحی دیجیتال

تصور کنید می‌خواهید یک مدار دیجیتال طراحی کنید که چراغ راهنمای یک چهارراه را کنترل کند. یا می‌خواهید سیستمی طراحی کنید که تشخیص دهد یک عدد زوج است یا فرد. یا شاید بخواهید یک ماشین‌حساب ساده بسازید.

اولین سوالی که باید پاسخ دهید این است: **مدار من برای هر ترکیب ممکن از ورودی‌ها، چه خروجی‌ای باید تولید کند؟**

پاسخ این سوال را **جدول درستی (Truth Table)** می‌دهد. جدول درستی مانند یک **قرارداد کامل** است که رفتار مدار را برای **همه حالت‌های ممکن** مشخص می‌کند. قبل از اینکه حتی یک گیت منطقی بچینیم یا یک خط VHDL بنویسیم، جدول درستی به ما می‌گوید که مدار نهایی باید دقیقاً چه کاری انجام دهد.

---

## ۱. جدول درستی چیست؟ تعریف جامع

**جدول درستی (Truth Table)** یک جدول ریاضی است که **همه ترکیب‌های ممکن ورودی** یک مدار منطقی را نشان می‌دهد و برای هر ترکیب، **مقدار خروجی** را مشخص می‌کند.

### ساختار یک جدول درستی

```
┌─────────────┬─────────────┬─────────────┐
│  ورودی ۱    │  ورودی ۲    │  خروجی     │
├─────────────┼─────────────┼─────────────┤
│      ۰      │      ۰      │      ?      │
│      ۰      │      ۱      │      ?      │
│      ۱      │      ۰      │      ?      │
│      ۱      │      ۱      │      ?      │
└─────────────┴─────────────┴─────────────┘
```

### قیاس با دنیای واقعی

جدول درستی مانند **دفترچه راهنمای یک دستگاه** است:
- ورودی‌ها = دکمه‌هایی که کاربر می‌زند
- خروجی‌ها = واکنش دستگاه
- هر سطر = یک سناریوی خاص

مثلاً برای یک چراغ قوه:
```
دکمه فشار داده شده؟ | چراغ روشن است؟
────────────────────┼─────────────────
      نه (۰)        │     نه (۰)
      بله (۱)       │     بله (۱)
```

## ۲. چرا جدول درستی مهم است؟

جدول درستی **چهار نقش کلیدی** در طراحی دیجیتال دارد:

### ۱. مستندسازی (Documentation)
قبل از شروع طراحی، دقیقاً مشخص می‌کند که مدار باید چه رفتاری داشته باشد.

### ۲. طراحی (Design)
از جدول درستی می‌توان عبارت بولی و سپس مدار را استخراج کرد.

### ۳. تحلیل (Analysis)
با داشتن یک مدار، می‌توان جدول درستی آن را محاسبه کرد و فهمید که مدار چه کاری انجام می‌دهد.

### ۴. راستی‌آزمایی (Verification)
پس از نوشتن کد VHDL، می‌توان خروجی شبیه‌سازی را با جدول درستی مقایسه کرد.

### زنجیره کامل طراحی

```
نیاز (Requirement)
       ↓
جدول درستی (Truth Table)
       ↓
عبارت بولی (Boolean Expression)
       ↓
ساده‌سازی (Simplification)
       ↓
مدار منطقی (Logic Circuit)
       ↓
VHDL
       ↓
شبیه‌سازی (Simulation)
       ↓
مقایسه با جدول درستی (Verification)
       ↓
✅ تأیید (PASS)
```

## ۳. تعداد حالت‌های ممکن

تعداد ردیف‌های یک جدول درستی به **تعداد ورودی‌ها** بستگی دارد.

### فرمول کلی

```
تعداد ترکیب‌ها = ۲ⁿ
که n = تعداد ورودی‌ها
```

### مثال‌ها

| تعداد ورودی | تعداد ترکیب‌ها | توضیح |
|------------|---------------|--------|
| ۱ | ۲¹ = ۲ | ۰, ۱ |
| ۲ | ۲² = ۴ | ۰۰, ۰۱, ۱۰, ۱۱ |
| ۳ | ۲³ = ۸ | ۰۰۰, ۰۰۱, ۰۱۰, ۰۱۱, ۱۰۰, ۱۰۱, ۱۱۰, ۱۱۱ |
| ۴ | ۲⁴ = ۱۶ | ... |
| ۸ | ۲⁸ = ۲۵۶ | یک بایت کامل |
| ۱۰ | ۲¹⁰ = ۱۰۲۴ | بیش از هزار حالت |

### نکته مهم

برای مدارهای با ورودی زیاد (مثلاً ۱۰ ورودی یا بیشتر)، جدول درستی کامل بسیار بزرگ می‌شود. در این موارد از روش‌های دیگری مثل **جبر بولی**، **نقشه کارنو**، یا **شبیه‌سازی** استفاده می‌کنیم.

| A | Y |
|---|:---:|

| ۱ | ۰ |

**قانون:** خروجی دقیقاً برعکس ورودی است.

## ۶. ساخت جدول درستی برای مدارهای ترکیبی

### روش گام‌به‌گام

۱. **شناسایی ورودی‌ها و خروجی‌ها**
۲. **تعیین تعداد ترکیب‌ها** (`۲ⁿ`)
۳. **نوشتن همه ترکیب‌های ورودی** (به ترتیب باینری)
۴. **محاسبه خروجی** برای هر ترکیب (با استفاده از سیگنال‌های میانی)

### مثال ۱: مدار ساده با دو گیت

**مدار:**
```
A ───┐
     AND ───┐
B ───┘      │
            OR ─── Y
C ──────────┘
```

**معادله:** `Y = (A · B) + C`

**مرحله ۱:** ورودی‌ها = A, B, C (۳ ورودی → ۸ حالت)

**مرحله ۲:** سیگنال میانی `X = A · B`

**مرحله ۳:** جدول کامل

| A | B | C | X = A·B | Y = X + C |
|---|---|---|---|:---:|
| ۰ | ۰ | ۰ | ۰ | ۰ |
| ۰ | ۰ | ۱ | ۰ | ۱ |
| ۰ | ۱ | ۰ | ۰ | ۰ |
| ۰ | ۱ | ۱ | ۰ | ۱ |
| ۱ | ۰ | ۰ | ۰ | ۰ |
| ۱ | ۰ | ۱ | ۰ | ۱ |
| ۱ | ۱ | ۰ | ۱ | ۱ |
| ۱ | ۱ | ۱ | ۱ | ۱ |

### مثال ۲: مدار با سه گیت

**مدار:**
```
A ────┐
      XOR ──┐
B ────┘     │
            AND ─── Y
C ────┐     │
      NOT ──┘
D ────┘
```

**معادله:** `Y = (A ⊕ B) · (C · D)`

**مرحله ۱:** ورودی‌ها = A, B, C, D (۴ ورودی → ۱۶ حالت)

**مرحله ۲:** سیگنال‌های میانی:
- `X = A ⊕ B`
- `Z = ¬C`
- `W = Z · D`

**مرحله ۳:** جدول کامل (نمونه‌ای از سطرها)

| A | B | C | D | X=A⊕B | Z=¬C | W=Z·D | Y=X·W |
|---|---|---|---|:---:|:---:|:---:|:---:|
| ۰ | ۰ | ۰ | ۰ | ۰ | ۱ | ۰ | ۰ |
| ۰ | ۰ | ۰ | ۱ | ۰ | ۱ | ۱ | ۰ |
| ۰ | ۰ | ۱ | ۰ | ۰ | ۰ | ۰ | ۰ |
| ۰ | ۰ | ۱ | ۱ | ۰ | ۰ | ۰ | ۰ |
| ... | ... | ... | ... | ... | ... | ... | ... |
| ۱ | ۱ | ۰ | ۱ | ۰ | ۱ | ۱ | ۰ |
| ۱ | ۱ | ۱ | ۱ | ۰ | ۰ | ۰ | ۰ |

## ۷. از جدول درستی به عبارت بولی

این یکی از مهم‌ترین مهارت‌ها در طراحی دیجیتال است.

### روش Sum of Products (SOP)

۱. **ردیف‌هایی که خروجی `1` دارند را پیدا کنید**
۲. **برای هر ردیف، یک Minterm بسازید**
۳. **همه Mintermها را با OR به هم وصل کنید**

### مثال: تشخیص عدد زوج (با ۳ بیت)

**مسئله:** مداری طراحی کنید که تشخیص دهد یک عدد ۳ بیتی زوج است یا فرد.

**ورودی‌ها:** A (MSB), B, C (LSB)

**خروجی:** Y = ۱ اگر عدد زوج باشد (LSB = ۰)

**جدول درستی:**

| A | B | C | عدد | Y (زوج؟) |
|---|---|---|---|:---:|
| ۰ | ۰ | ۰ | ۰ | ۱ |
| ۰ | ۰ | ۱ | ۱ | ۰ |
| ۰ | ۱ | ۰ | ۲ | ۱ |
| ۰ | ۱ | ۱ | ۳ | ۰ |
| ۱ | ۰ | ۰ | ۴ | ۱ |
| ۱ | ۰ | ۱ | ۵ | ۰ |
| ۱ | ۱ | ۰ | ۶ | ۱ |
| ۱ | ۱ | ۱ | ۷ | ۰ |

**ردیف‌های با خروجی ۱:** ۰۰۰, ۰۱۰, ۱۰۰, ۱۱۰

**Mintermها:**
- ۰۰۰: `¬A · ¬B · ¬C`
- ۰۱۰: `¬A · B · ¬C`
- ۱۰۰: `A · ¬B · ¬C`
- ۱۱۰: `A · B · ¬C`

**عبارت SOP:**
```
Y = ¬A·¬B·¬C + ¬A·B·¬C + A·¬B·¬C + A·B·¬C
```

**ساده‌سازی:**
```
Y = ¬C · (¬A·¬B + ¬A·B + A·¬B + A·B)
  = ¬C · ((¬A·¬B + ¬A·B) + (A·¬B + A·B))
  = ¬C · (¬A·(¬B+B) + A·(¬B+B))
  = ¬C · (¬A·1 + A·1)
  = ¬C · (¬A + A)
  = ¬C · 1
  = ¬C
```

**نتیجه:** `Y = ¬C` — عدد زوج است اگر LSB صفر باشد! ✓

## ۸. Minterm و Maxterm

### Minterm (حاصل‌ضرب کامل)

یک Minterm یک **عبارت AND** است که **همه متغیرها** را شامل می‌شود.

**قانون ساخت:**
- اگر متغیر = ۱ → از خود متغیر استفاده کن
- اگر متغیر = ۰ → از نقیض متغیر استفاده کن

**مثال (۳ متغیر A, B, C):**

| A | B | C | Minterm | نام |
|---|---|---|---|:---:|
| ۰ | ۰ | ۰ | `¬A·¬B·¬C` | m₀ |
| ۰ | ۰ | ۱ | `¬A·¬B·C` | m₁ |
| ۰ | ۱ | ۰ | `¬A·B·¬C` | m₂ |
| ۰ | ۱ | ۱ | `¬A·B·C` | m₃ |
| ۱ | ۰ | ۰ | `A·¬B·¬C` | m₄ |
| ۱ | ۰ | ۱ | `A·¬B·C` | m₅ |
| ۱ | ۱ | ۰ | `A·B·¬C` | m₆ |
| ۱ | ۱ | ۱ | `A·B·C` | m₇ |

### Maxterm (مجموع کامل)

یک Maxterm یک **عبارت OR** است که **همه متغیرها** را شامل می‌شود.

**قانون ساخت:**
- اگر متغیر = ۰ → از خود متغیر استفاده کن
- اگر متغیر = ۱ → از نقیض متغیر استفاده کن

**مثال (۳ متغیر A, B, C):**

| A | B | C | Maxterm | نام |
|---|---|---|---|:---:|
| ۰ | ۰ | ۰ | `A+B+C` | M₀ |
| ۰ | ۰ | ۱ | `A+B+¬C` | M₁ |
| ۰ | ۱ | ۰ | `A+¬B+C` | M₂ |
| ۰ | ۱ | ۱ | `A+¬B+¬C` | M₃ |
| ۱ | ۰ | ۰ | `¬A+B+C` | M₄ |
| ۱ | ۰ | ۱ | `¬A+B+¬C` | M₅ |
| ۱ | ۱ | ۰ | `¬A+¬B+C` | M₆ |
| ۱ | ۱ | ۱ | `¬A+¬B+¬C` | M₇ |

### رابطه Minterm و Maxterm

هر Minterm و Maxterm با اندیس یکسان، **مکمل** یکدیگرند:

```
mᵢ = ¬Mᵢ
Mᵢ = ¬mᵢ
```

## ۹. Don't Care (مقادیر بی‌اهمیت)

در برخی مدارها، **همه ترکیب‌های ورودی** معنی ندارند یا مهم نیستند. در این موارد از **Don't Care** استفاده می‌کنیم.

### کاربرد Don't Care

۱. **کاهش تعداد گیت‌ها** در طراحی
۲. **ساده‌سازی** عبارات بولی
۳. **انعطاف‌پذیری** در طراحی

### مثال: نمایش اعداد روی ۷-سگمنت

برای نمایش اعداد ۰ تا ۹ روی یک نمایشگر ۷-سگمنت، ۶ ترکیب باقیمانده (۱۰ تا ۱۵) **هرگز اتفاق نمی‌افتند**، پس می‌توان آنها را Don't Care در نظر گرفت.

**جدول درستی برای بخشی از دیکدر ۷-سگمنت:**

| عدد (BCD) | بخش a | بخش b | ... |
|----------|:-----:|:-----:|-----|
| ۰۰۰۰ (۰) | ۱ | ۱ | ... |
| ۰۰۰۱ (۱) | ۰ | ۱ | ... |
| ... | ... | ... | ... |
| ۱۰۰۱ (۹) | ۱ | ۱ | ... |
| ۱۰۱۰ (۱۰) | X | X | ... |
| ۱۰۱۱ (۱۱) | X | X | ... |
| ۱۱۰۰ (۱۲) | X | X | ... |
| ۱۱۰۱ (۱۳) | X | X | ... |
| ۱۱۱۰ (۱۴) | X | X | ... |
| ۱۱۱۱ (۱۵) | X | X | ... |

### استفاده از Don't Care در K-Map

در نقشه کارنو، از Xها می‌توان برای **گروه‌بندی بزرگ‌تر** و ساده‌سازی بیشتر استفاده کرد.

## ۱۰. جدول درستی و VHDL

### ۱۰.۱. طراحی بر اساس جدول درستی

**جدول درستی:**

| A | B | Y |
|---|---|:---:|
| ۰ | ۰ | ۰ |
| ۰ | ۱ | ۱ |
| ۱ | ۰ | ۱ |
| ۱ | ۱ | ۰ |

**تشخیص:** این XOR است.

**VHDL:**
```vhdl
y <= a xor b;
```

### ۱۰.۲. جدول درستی پیچیده‌تر

**جدول درستی (۳ ورودی):**

| A | B | C | Y |
|---|---|---|---|
| ۰ | ۰ | ۰ | ۰ |
| ۰ | ۰ | ۱ | ۱ |
| ۰ | ۱ | ۰ | ۰ |
| ۰ | ۱ | ۱ | ۱ |
| ۱ | ۰ | ۰ | ۱ |
| ۱ | ۰ | ۱ | ۰ |
| ۱ | ۱ | ۰ | ۰ |
| ۱ | ۱ | ۱ | ۱ |

**عبارت SOP:**
```
Y = m₁ + m₃ + m₄ + m₇
  = ¬A·¬B·C + ¬A·B·C + A·¬B·¬C + A·B·C
```

**VHDL (با استفاده از عبارت بولی):**
```vhdl
y <= ((not a) and (not b) and c) or
     ((not a) and b and c) or
     (a and (not b) and (not c)) or
     (a and b and c);
```

**VHDL (با استفاده از case):**
```vhdl
process(a, b, c)
begin
    case a & b & c is
        when "001" | "011" | "100" | "111" =>
            y <= '1';
        when others =>
            y <= '0';
    end case;
end process;
```

**VHDL (با استفاده از تابع):**
```vhdl
y <= '1' when (a = '0' and b = '0' and c = '1') or
              (a = '0' and b = '1' and c = '1') or
              (a = '1' and b = '0' and c = '0') or
              (a = '1' and b = '1' and c = '1')
    else '0';
```

## ۱۲. Half Adder — اولین پروژه کامل

**Half Adder** یک مدار است که دو بیت را جمع می‌کند و دو خروجی دارد:
- **Sum** = جمع (بدون نقلی)
- **Carry** = نقلی (به بیت بعدی)

### جدول درستی Half Adder

| A | B | Sum | Carry |
|---|---|:---:|:---:|
| ۰ | ۰ | ۰ | ۰ |
| ۰ | ۱ | ۱ | ۰ |
| ۱ | ۰ | ۱ | ۰ |
| ۱ | ۱ | ۰ | ۱ |

### استخراج عبارات بولی

از جدول درستی:
```
Sum   = A ⊕ B  (XOR)
Carry = A · B  (AND)
```

### مدار Half Adder

```
A ────┐
      XOR ──── Sum
B ────┤
      │
      AND ──── Carry
      │
B ────┘
```

### VHDL برای Half Adder

```vhdl
library ieee;
use ieee.std_logic_1164.all;

entity half_adder is
    port (
        a, b  : in  std_logic;
        sum   : out std_logic;
        carry : out std_logic
    );
end entity;

architecture rtl of half_adder is
begin
    sum   <= a xor b;
    carry <= a and b;
end architecture;
```

### زنجیره یادگیری Half Adder

```
نیاز: جمع دو بیت
       ↓
جدول درستی (۴ حالت)
       ↓
عبارات بولی (Sum = XOR, Carry = AND)
       ↓
مدار منطقی (یک XOR + یک AND)
       ↓
VHDL
       ↓
شبیه‌سازی
       ↓
تأیید با جدول درستی
```

## ۱۳. Full Adder — پروژه بعدی

Full Adder سه بیت را جمع می‌کند: دو بیت ورودی + نقلی ورودی (Carry In)

### جدول درستی Full Adder

| A | B | Cin | Sum | Cout |
|---|---|:---:|:---:|:---:|
| ۰ | ۰ | ۰ | ۰ | ۰ |
| ۰ | ۰ | ۱ | ۱ | ۰ |
| ۰ | ۱ | ۰ | ۱ | ۰ |
| ۰ | ۱ | ۱ | ۰ | ۱ |
| ۱ | ۰ | ۰ | ۱ | ۰ |
| ۱ | ۰ | ۱ | ۰ | ۱ |
| ۱ | ۱ | ۰ | ۰ | ۱ |
| ۱ | ۱ | ۱ | ۱ | ۱ |

### استخراج عبارات بولی

از جدول درستی:
```
Sum   = A ⊕ B ⊕ Cin
Cout  = (A · B) + (A · Cin) + (B · Cin)
```

### VHDL برای Full Adder

```vhdl
library ieee;
use ieee.std_logic_1164.all;

entity full_adder is
    port (
        a, b, cin : in  std_logic;
        sum       : out std_logic;
        cout      : out std_logic
    );
end entity;

architecture rtl of full_adder is
begin
    sum  <= a xor b xor cin;
    cout <= (a and b) or (a and cin) or (b and cin);
end architecture;
```

## ۱۸. جمع‌بندی نهایی

### آنچه باید به خاطر بسپارید

۱. **جدول درستی** = لیست کامل همه ترکیب‌های ورودی و خروجی‌های متناظر
۲. **تعداد ردیف‌ها** = ۲ⁿ (n = تعداد ورودی‌ها)
۳. **کاربردها:** طراحی، تحلیل، مستندسازی، تأیید
۴. **Minterm** = AND همه متغیرها (برای خروجی ۱)
۵. **Maxterm** = OR همه متغیرها (برای خروجی ۰)
۶. **Don't Care (X)** = حالت‌هایی که مهم نیستند
۷. **SOP** = جمع Mintermها (AND → OR)
۸. **POS** = ضرب Maxtermها (OR → AND)
۹. **Half Adder** = اولین پروژه کامل با ۲ ورودی و ۲ خروجی
۱۰. **Testbench** = از جدول درستی برای تأیید مدار استفاده می‌کند

### جدول درستی در VHDL

```
جدول درستی  ←→  VHDL
AND         ←→  y <= a and b;
OR          ←→  y <= a or b;
XOR         ←→  y <= a xor b;
Mintermها   ←→  y <= m1 or m2 or m3;
Test Vectors ←→  assert y = expected;
```

### پیام نهایی

جدول درستی **نقشه راه طراحی دیجیتال** است. قبل از اینکه حتی یک گیت منطقی بچینید یا یک خط کد VHDL بنویسید، جدول درستی به شما می‌گوید که مدارتان دقیقاً چه کاری باید انجام دهد. این سادگی و شفافیت، جدول درستی را به یکی از قدرتمندترین ابزارهای مهندسی دیجیتال تبدیل کرده است.

با تسلط بر جدول درستی، شما می‌توانید:
- هر مدار ترکیبی را تحلیل کنید
- هر مدار ترکیبی را طراحی کنید
- کد VHDL خود را تأیید کنید
- مدارهای پیچیده‌تر را درک کنید
