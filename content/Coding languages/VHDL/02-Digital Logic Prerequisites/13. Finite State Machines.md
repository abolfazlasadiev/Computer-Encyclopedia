# Finite State Machines — ماشین‌های حالت متناهی

**Finite State Machine یا FSM** یکی از مهم‌ترین مفاهیم در طراحی سیستم‌های دیجیتال است.

اگر در مباحث قبلی مدارهایی مثل:

- Logic Gates
    
- MUX
    
- Decoder
    
- Adder
    

را بررسی کردیم، همه عمدتاً بر اساس **ورودی فعلی** خروجی تولید می‌کردند.

اما FSM یک قدم جلوتر می‌رود:

> **خروجی سیستم علاوه بر ورودی، به وضعیت فعلی سیستم نیز وابسته است.**

به همین دلیل FSM پایه‌ی بسیاری از سیستم‌های واقعی است:

```text
Traffic Light
Vending Machine
Elevator
UART Controller
CPU Control Unit
Washing Machine
Digital Lock
Protocol Controller
```

---

# 1. FSM چیست؟

یک FSM سیستمی است که در هر لحظه در یکی از تعداد محدودی **State** قرار دارد.

مثلاً یک چراغ راهنمایی:

```text
RED
 ↓
GREEN
 ↓
YELLOW
 ↓
RED
```

سیستم همیشه یکی از این حالت‌ها را دارد:

```text
State = RED
State = GREEN
State = YELLOW
```

و بر اساس شرایط، از یک State به State دیگر منتقل می‌شود.

---

# 2. چهار مفهوم اصلی FSM

هر FSM حداقل این مفاهیم را دارد:

```text
Current State
      ↓
Input
      ↓
Next State
      ↓
Output
```

یا دقیق‌تر:

```text
             ┌─────────────────┐
             │                 │
             ↓                 │
      ┌──────────────┐         │
Input │ Next-State   │         │
─────→│   Logic      │─────────┤
      └──────────────┘         │
             ↓                 │
        Next State              │
             ↓                 │
      ┌──────────────┐         │
Clock │ State        │         │
─────→│ Register     │─────────┘
      └──────────────┘
             ↓
       Current State
             ↓
      Output Logic
             ↓
          Output
```

پس سه بخش بسیار مهم داریم:

```text
State Register
Next-State Logic
Output Logic
```

---

# 3. State چیست؟

State یعنی:

> **سیستم در حال حاضر در چه وضعیت منطقی قرار دارد؟**

مثلاً برای یک درِ اتوماتیک:

```text
CLOSED
OPENING
OPEN
CLOSING
```

سیستم در هر لحظه یکی از این Stateها را دارد.

مثلاً:

```text
Current State = OPEN
```

اگر سنسور درخواست بسته‌شدن بدهد:

```text
OPEN
 ↓
CLOSING
```

---

# 4. State Transition

تغییر از یک State به State دیگر را **Transition** می‌گوییم.

مثلاً:

```text
CLOSED ──open──→ OPENING
```

یا:

```text
OPEN ──close──→ CLOSING
```

معمولاً Transition به یک شرط یا Input وابسته است.

---

# 5. State Diagram

یکی از مهم‌ترین ابزارهای طراحی FSM، **State Diagram** است.

مثلاً Traffic Light:

```text
        ┌──────────┐
        │          ↓
      ┌─────┐   ┌───────┐
      │ RED │──→│ GREEN │
      └─────┘   └───────┘
                    │
                    ↓
                ┌────────┐
                │ YELLOW │
                └────────┘
                    │
                    └────→ RED
```

این Diagram قبل از نوشتن VHDL بسیار مهم است.

---

# 6. State Transition Table

همین FSM را می‌توان با جدول نشان داد.

|Current State|Input|Next State|
|---|---|---|
|RED|—|GREEN|
|GREEN|—|YELLOW|
|YELLOW|—|RED|

در FSMهای واقعی معمولاً Inputها هم مهم هستند.

مثلاً Door Controller:

|Current State|Sensor|Next State|
|---|---|---|
|CLOSED|0|CLOSED|
|CLOSED|1|OPENING|
|OPENING|0|OPENING|
|OPENING|1|OPEN|
|OPEN|0|CLOSING|
|OPEN|1|OPEN|

---

# 7. چرا FSM به Clock نیاز دارد؟

FSM معمولاً یک **Sequential Circuit** است.

State باید در جایی ذخیره شود.

این کار توسط Flip-Flopها انجام می‌شود:

```text
             ┌───────────────┐
             │ State Register│
Clock ──────→│               │
             └───────┬───────┘
                     │
               Current State
                     ↓
              Next-State Logic
                     ↓
                 Next State
                     │
                     └──────→ State Register
```

پس:

```text
Clock
  ↓
State Register
  ↓
Current State
```

---

# 8. FSM از چه مدارهایی ساخته می‌شود؟

یک FSM معمولاً ترکیبی از:

```text
Flip-Flops
+
Combinational Logic
```

است.

یعنی:

```text
Combinational Logic
       +
Sequential Logic
       ↓
      FSM
```

این یکی از مهم‌ترین ارتباط‌ها بین مباحث قبلی است.

---

# 9. Moore Machine

در **Moore FSM** خروجی فقط به Current State وابسته است:

```text
Output = f(Current State)
```

یعنی:

```text
State
  ↓
Output
```

مثلاً:

```text
RED    → Red Light
GREEN  → Green Light
YELLOW → Yellow Light
```

Input مستقیماً خروجی را تغییر نمی‌دهد؛ ابتدا State تغییر می‌کند.

---

# 10. Mealy Machine

در **Mealy FSM** خروجی به State و Input وابسته است:

```text
Output = f(Current State, Input)
```

یعنی:

```text
Current State ──┐
                ├──→ Output
Input ──────────┘
```

در نتیجه ممکن است Output با تغییر Input تغییر کند، حتی قبل از تغییر State.

---

# 11. Moore vs Mealy

|ویژگی|Moore|Mealy|
|---|---|---|
|Output وابسته به|State|State + Input|
|تغییر Output|معمولاً با تغییر State|می‌تواند با Input تغییر کند|
|طراحی|ساده‌تر|گاهی سریع‌تر/کم‌State‌تر|
|حساسیت به Input|غیرمستقیم|مستقیم|
|Glitch احتمالاً|کمتر در خروجی State-based|بیشتر باید مراقبت شود|

به صورت خلاصه:

```text
Moore:
State → Output

Mealy:
State + Input → Output
```

---

# 12. مثال ساده — Traffic Light

یک سیستم Traffic Light طراحی کنیم.

Stateها:

```text
RED
GREEN
YELLOW
```

Transition:

```text
RED
 ↓
GREEN
 ↓
YELLOW
 ↓
RED
```

اگر هر State مثلاً بعد از یک زمان مشخص تغییر کند:

```text
RED    → 10 sec
GREEN  → 10 sec
YELLOW → 3 sec
```

اینجا یک نکته مهم ظاهر می‌شود:

> FSM خودش مفهوم «زمان» را ایجاد نمی‌کند.

برای زمان‌بندی به Counter نیاز داریم.

پس:

```text
Counter
   ↓
Timer / Timeout
   ↓
FSM
```

این یک مثال عالی از ترکیب دو مبحث قبلی است.

---

# 13. مثال مهم‌تر — Vending Machine

فرض کنیم دستگاه نوشابه داریم.

قیمت:

```text
10 units
```

کاربر می‌تواند:

```text
5
10
```

واحد وارد کند.

Stateها:

```text
S0 = 0 units
S5 = 5 units
S10 = 10 units
```

Transition:

```text
        5
S0 ─────────→ S5
│             │
│10           │5
↓             ↓
S10 ←─────────┘
```

اگر به `S10` برسیم:

```text
Dispense = 1
```

سپس:

```text
S10 → S0
```

این یک FSM واقعی و بسیار خوب برای آموزش است.

---

# 14. State Encoding

Stateها باید در Hardware به صورت بیت ذخیره شوند.

مثلاً سه State:

```text
RED
GREEN
YELLOW
```

می‌توانیم Binary Encoding داشته باشیم:

```text
RED    = 00
GREEN  = 01
YELLOW = 10
```

این را **State Encoding** می‌گوییم.

---

# 15. Binary Encoding

در Binary Encoding برای `N` State تقریباً به:

```text
ceil(log₂(N))
```

Flip-Flop نیاز داریم.

مثلاً:

```text
4 States
↓
2 Flip-Flops
```

چون:

```text
2² = 4
```

برای:

```text
8 States
```

نیاز داریم:

```text
3 Flip-Flops
```

---

# 16. One-Hot Encoding

در One-Hot برای هر State یک بیت داریم.

مثلاً چهار State:

```text
S0 = 0001
S1 = 0010
S2 = 0100
S3 = 1000
```

در هر لحظه فقط یک بیت `1` است.

این دقیقاً با Decoderهایی که قبلاً یاد گرفتیم ارتباط دارد.

```text
Binary State
     ↓
Decoder
     ↓
One-Hot State
```

در FPGAها One-Hot Encoding می‌تواند در برخی طراحی‌ها مزایای پیاده‌سازی داشته باشد، هرچند ابزار Synthesis معمولاً خودش می‌تواند State Encoding مناسب را انتخاب یا بهینه کند.

---

# 17. State Register

State Register وظیفه دارد Current State را ذخیره کند.

مثلاً:

```text
        ┌────────────────┐
        │ State Register │
        └───────┬────────┘
                │
          Current State
                ↓
        Next-State Logic
                ↓
           Next State
                │
                └───────────┐
                            ↓
                     State Register
```

در VHDL معمولاً این بخش در یک Process کلاک‌دار نوشته می‌شود.

---

# 18. الگوی استاندارد FSM در VHDL

یکی از مهم‌ترین Coding Patternهای VHDL:

```vhdl
architecture rtl of controller is

    type state_type is (
        IDLE,
        RUN,
        DONE
    );

    signal state, next_state : state_type;

begin

    -- State Register
    process(clk, reset)
    begin
        if reset = '1' then
            state <= IDLE;

        elsif rising_edge(clk) then
            state <= next_state;
        end if;
    end process;


    -- Next-State Logic
    process(all)
    begin
        next_state <= state;

        case state is

            when IDLE =>
                if start = '1' then
                    next_state <= RUN;
                end if;

            when RUN =>
                if finished = '1' then
                    next_state <= DONE;
                end if;

            when DONE =>
                next_state <= IDLE;

            when others =>
                next_state <= IDLE;

        end case;
    end process;

end architecture;
```

این الگو را دانشجو باید خیلی خوب یاد بگیرد.

---

# 19. سه بخش مهم این کد

### بخش اول — State Type

```vhdl
type state_type is (
    IDLE,
    RUN,
    DONE
);
```

Stateها را تعریف می‌کند.

---

### بخش دوم — State Register

```vhdl
process(clk, reset)
begin
    if reset = '1' then
        state <= IDLE;

    elsif rising_edge(clk) then
        state <= next_state;
    end if;
end process;
```

این بخش **Sequential** است.

---

### بخش سوم — Next-State Logic

```vhdl
process(all)
begin
    case state is
        ...
    end case;
end process;
```

این بخش **Combinational** است.

پس:

```text
State Register
    ↓
Sequential

Next-State Logic
    ↓
Combinational
```

---

# 20. Moore FSM در VHDL

مثلاً:

```vhdl
process(all)
begin

    case state is

        when IDLE =>
            led <= '0';

        when RUN =>
            led <= '1';

        when DONE =>
            led <= '0';

        when others =>
            led <= '0';

    end case;

end process;
```

اینجا:

```text
LED = f(State)
```

پس Moore است.

---

# 21. Mealy FSM در VHDL

مثلاً:

```vhdl
process(all)
begin

    done <= '0';

    case state is

        when RUN =>
            if finished = '1' then
                done <= '1';
            end if;

        when others =>
            done <= '0';

    end case;

end process;
```

اینجا:

```text
done = f(state, finished)
```

پس Mealy است.

---

# 22. Reset در FSM

Reset بسیار مهم است.

مثلاً می‌خواهیم سیستم همیشه از:

```text
IDLE
```

شروع کند.

پس:

```vhdl
if reset = '1' then
    state <= IDLE;
```

یعنی:

```text
Reset
  ↓
Known State
  ↓
IDLE
```

بدون Reset مناسب، State اولیه ممکن است در طراحی یا Simulation رفتار نامشخصی داشته باشد.

---

# 23. Synchronous و Asynchronous Reset

دو روش رایج:

### Asynchronous Reset

```vhdl
process(clk, reset)
begin
    if reset = '1' then
        state <= IDLE;

    elsif rising_edge(clk) then
        state <= next_state;
    end if;
end process;
```

Reset بدون منتظر ماندن برای Clock اثر می‌کند.

---

### Synchronous Reset

```vhdl
process(clk)
begin
    if rising_edge(clk) then

        if reset = '1' then
            state <= IDLE;
        else
            state <= next_state;
        end if;

    end if;
end process;
```

Reset فقط روی لبه Clock اعمال می‌شود.

در FPGAهای واقعی، انتخاب نوع Reset به معماری، ابزار و استاندارد پروژه بستگی دارد؛ مهم این است که دانشجو تفاوت مفهومی آنها را بداند.

---

# 24. Default Assignment

در Next-State Logic بهتر است رفتار پیش‌فرض مشخص باشد:

```vhdl
next_state <= state;
```

مثلاً:

```vhdl
process(all)
begin

    next_state <= state;

    case state is

        when IDLE =>
            if start = '1' then
                next_state <= RUN;
            end if;

        ...

    end case;

end process;
```

این باعث می‌شود اگر شرطی برقرار نبود:

```text
Next State = Current State
```

باشد.

این یک Coding Pattern مهم برای جلوگیری از **Latch ناخواسته** در منطق ترکیبی است.

---

# 25. `when others`

برای State Type نیز بهتر است حالت‌های غیرمنتظره را مدیریت کنیم:

```vhdl
when others =>
    next_state <= IDLE;
```

مثلاً اگر State Register به وضعیتی رسید که در طراحی تعریف نشده:

```text
Unknown / Invalid State
        ↓
       IDLE
```

این یک **Safe Recovery** ساده است.

---

# 26. FSM و Counter

یکی از مهم‌ترین ترکیب‌ها:

```text
FSM
+
Counter
```

مثلاً Traffic Light:

```text
FSM
 │
 ├── RED
 ├── GREEN
 └── YELLOW
```

و Counter:

```text
RED    → Count 10
GREEN  → Count 10
YELLOW → Count 3
```

وقتی Counter به مقدار مورد نظر رسید:

```text
timeout = 1
```

FSM State را تغییر می‌دهد.

پس:

```text
Clock
 ↓
Counter
 ↓
Timeout
 ↓
FSM
 ↓
Next State
```

---

# 27. FSM و Debouncing

در FPGA اگر Button را مستقیماً وارد FSM کنیم، ممکن است به دلیل **Mechanical Bounce** چند Transition ناخواسته ایجاد شود.

معمولاً:

```text
Button
 ↓
Synchronizer
 ↓
Debouncer
 ↓
FSM
```

این موضوع در پروژه‌های FPGA واقعی بسیار مهم است.

---

# 28. FSM و Synchronization

یک Input خارجی ممکن است با Clock داخلی هم‌زمان نباشد.

بنابراین معمولاً:

```text
External Signal
      ↓
Synchronizer
      ↓
FSM
```

قرار می‌گیرد.

این موضوع بعداً در بخش Advanced FPGA / Clock Domain Crossing بهتر آموزش داده می‌شود.

---

# 29. مثال کامل — Digital Door Lock

یک پروژه عالی برای FSM:

رمز:

```text
1011
```

فرض کنیم هر بیت رمز در هر Clock وارد می‌شود.

Stateها:

```text
IDLE
GOT_1
GOT_10
GOT_101
UNLOCKED
```

Transition:

```text
             1
IDLE ─────────────→ GOT_1
                     │
                     │ 0
                     ↓
                  GOT_10
                     │
                     │ 1
                     ↓
                 GOT_101
                     │
                     │ 1
                     ↓
                 UNLOCKED
```

اگر کاربر ورودی اشتباه بدهد:

```text
GOT_10 + wrong bit
        ↓
      IDLE
```

این پروژه به‌خوبی نشان می‌دهد FSM چگونه یک **Sequence Detector** را پیاده‌سازی می‌کند.

---

# 30. Sequence Detector

یک FSM می‌تواند دنبال یک Sequence خاص بگردد.

مثلاً:

```text
1011
```

Input:

```text
1 0 1 1
```

وقتی Sequence کامل شد:

```text
detected = 1
```

ساختار:

```text
Serial Input
     ↓
   FSM
     ↓
Sequence Detected
```

این یکی از بهترین پروژه‌های آموزشی FSM است.

---

# 31. FSM و UART

UART نیز پر از State است.

مثلاً Transmitter:

```text
IDLE
 ↓
START
 ↓
DATA0
 ↓
DATA1
 ↓
DATA2
 ↓
...
 ↓
STOP
 ↓
IDLE
```

Receiver نیز Stateهای مشابهی دارد.

پس:

```text
UART
 ↓
FSM + Counter + Shift Register
```

این مثال نشان می‌دهد چطور چند مبحث قبلی با هم ترکیب می‌شوند.

---

# 32. FSM و CPU

در CPU نیز Control Unit می‌تواند به شکل FSM طراحی شود.

مثلاً:

```text
FETCH
 ↓
DECODE
 ↓
EXECUTE
 ↓
MEMORY
 ↓
WRITEBACK
 ↓
FETCH
```

پس:

```text
CPU Control Unit
       ↓
      FSM
```

یکی از پروژه‌های پیشرفته دانشنامه می‌تواند ساخت یک CPU ساده باشد که Control Unit آن با FSM پیاده‌سازی شده است.

---

# 33. اشتباه رایج: FSM بدون Clock

دانشجو ممکن است فکر کند:

```vhdl
if input = '1' then
    state <= NEXT_STATE;
end if;
```

به‌تنهایی یک FSM کامل است.

اما State باید **ذخیره** شود.

بنابراین در طراحی synchronous:

```text
Combinational Logic
       ↓
Next State
       ↓
Flip-Flops
       ↓
Current State
```

Clock تعیین می‌کند State چه زمانی به Next State تبدیل شود.

---

# 34. FSM و Combinational vs Sequential

این یکی از مهم‌ترین جمع‌بندی‌ها است:

```text
              FSM
               │
       ┌───────┴────────┐
       ↓                ↓
Sequential          Combinational
       │                │
State Register     Next-State Logic
       │                │
   Clocked          Input + State
```

و اگر Moore باشد:

```text
State
  ↓
Output
```

اگر Mealy باشد:

```text
State + Input
      ↓
    Output
```

# 35. Testbench برای FSM

Testbench باید فقط ورودی‌ها را بررسی نکند.

باید **Sequence** را بررسی کند.

مثلاً برای Door Lock:

```text
Reset
 ↓
Input = 1
 ↓
Input = 0
 ↓
Input = 1
 ↓
Input = 1
 ↓
UNLOCKED
```

باید بررسی کنیم:

```text
Current State
Next State
Output
```

مثلاً با Assertions:

```vhdl
assert unlocked = '1'
    report "Unlock failed"
    severity error;
```

# 39. جایگاه FSM در مسیر VHDL

تا اینجا مسیر دانشجو تقریباً به این شکل می‌شود:

```text
Digital Logic
      ↓
Logic Gates
      ↓
Boolean Algebra
      ↓
Truth Tables
      ↓
Combinational Circuits
      ↓
MUX
      ↓
Decoder
      ↓
Adder / Comparator / ALU
      ↓
Sequential Circuits
      ↓
Flip-Flops
      ↓
Registers
      ↓
Counters
      ↓
FSM
```

و FSM نقطه‌ای است که دانشجو از **مدارهای ساده** وارد **طراحی سیستم‌های دیجیتال** می‌شود.

# 40. زنجیره‌ای که دانشجو باید در ذهن داشته باشد

مهم‌ترین چیزی که از این فصل باید یاد بگیرد:

```text
Problem
   ↓
Identify States
   ↓
State Diagram
   ↓
State Table
   ↓
State Encoding
   ↓
Next-State Logic
   ↓
State Register
   ↓
Output Logic
   ↓
VHDL
   ↓
Testbench
   ↓
Simulation
   ↓
Synthesis
   ↓
FPGA
```

و برای پروژه‌های واقعی:

```text
FSM
 │
 ├── Counter
 │
 ├── Register
 │
 ├── MUX
 │
 ├── Decoder
 │
 └── Shift Register
       ↓
   Digital System
```

### نکته کلیدی

اگر بخواهی یک جمله برای دانشجو باقی بماند:

> **Combinational Logic تصمیم می‌گیرد چه اتفاقی باید بیفتد؛ Sequential Logic به خاطر می‌سپارد که سیستم در چه وضعیتی قرار دارد؛ FSM این دو را برای ساختن رفتار یک سیستم دیجیتال به هم متصل می‌کند.**

این دقیقاً همان نقطه‌ای است که VHDL از «توصیف گیت‌ها» عبور می‌کند و وارد **طراحی سیستم‌های دیجیتال واقعی** می‌شود.
