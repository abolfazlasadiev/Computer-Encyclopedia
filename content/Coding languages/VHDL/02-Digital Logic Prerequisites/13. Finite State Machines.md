# Finite State Machines — ماشین‌های حالت متناهی (نسخه کامل و جامع با تحلیل عمیق)

## مقدمه: از مدارهای ساده تا سیستم‌های هوشمند

تا اینجا در مسیر یادگیری طراحی دیجیتال، با مفاهیم زیر آشنا شده‌اید:

- **گیت‌های منطقی:** بلوک‌های سازنده اصلی
- **مدارهای ترکیبی:** خروجی فقط به ورودی فعلی بستگی دارد (MUX، Decoder، Adder)
- **فلیپ‌فلاپ‌ها:** عناصر حافظه یک بیتی
- **ثبات‌ها:** گروهی از فلیپ‌فلاپ‌ها برای ذخیره چند بیت
- **شمارنده‌ها:** ثبات‌هایی که خودشان مقدار بعدی را تولید می‌کنند

اما سوال اساسی اینجاست: **چگونه می‌توانیم سیستمی طراحی کنیم که رفتار پیچیده‌تری داشته باشد؟** سیستمی که:
- وضعیت خود را به خاطر بسپارد
- بر اساس ورودی‌ها تصمیم‌گیری کند
- دنباله‌ای از اقدامات را انجام دهد
- به رویدادهای خارجی واکنش نشان دهد

پاسخ در **ماشین‌های حالت متناهی (Finite State Machines — FSM)** نهفته است. FSM قلب تمام سیستم‌های دیجیتال هوشمند است: از یک چراغ راهنمایی ساده تا یک پردازنده قدرتمند.

---

## ۱. ماشین حالت متناهی چیست؟ تعریف جامع و عمیق

**ماشین حالت متناهی (Finite State Machine)** یک مدل ریاضی برای توصیف سیستم‌هایی است که در هر لحظه در یکی از **تعداد محدودی از حالت‌ها (States)** قرار دارند و بر اساس **ورودی‌های فعلی** و **حالت فعلی**، به حالت بعدی می‌روند و **خروجی** تولید می‌کنند.

### تعریف رسمی

یک FSM با پنج‌تایی زیر تعریف می‌شود:

```
M = (S, I, O, δ, λ)

که در آن:
S = مجموعه محدود از Stateها
I = مجموعه محدود از ورودی‌ها (Inputs)
O = مجموعه محدود از خروجی‌ها (Outputs)
δ = تابع انتقال حالت: S × I → S
λ = تابع خروجی: S × I → O (Mealy) یا S → O (Moore)
```

### قیاس با دنیای واقعی

یک FSM مانند **یک دستگاه قهوه‌ساز هوشمند** است:
- **حالت‌ها (States):** خاموش، آماده، در حال دم‌آوری، قهوه آماده
- **ورودی‌ها (Inputs):** دکمه روشن، دکمه قهوه، سنسور آب، سنسور دما
- **خروجی‌ها (Outputs):** چراغ‌ها، المنت گرمایش، پمپ، نمایشگر
- **انتقال حالت (Transitions):** با فشار دکمه روشن از خاموش به آماده می‌رود
- **خروجی:** در حالت در حال دم‌آوری، المنت روشن است

---

## ۲. چهار مفهوم اصلی FSM

هر FSM از چهار بخش اصلی تشکیل شده است:

### ۱. State (حالت)
وضعیت فعلی سیستم. State در **ثبات حالت (State Register)** ذخیره می‌شود.

### ۲. Input (ورودی)
سیگنال‌هایی که از خارج به سیستم می‌رسند و بر انتقال حالت تأثیر می‌گذارند.

### ۳. Next State (حالت بعدی)
حالتی که سیستم پس از دریافت ورودی و در لبه Clock به آن می‌رود.

### ۴. Output (خروجی)
سیگنال‌هایی که سیستم تولید می‌کند و به خارج ارسال می‌شود.

### مدل کلی FSM

```
        ┌─────────────────────────────────────────┐
        │                                         │
        │    ┌───────────────────────────────┐    │
Input ──┼───→│      Next-State Logic        │    │
        │    │      (Combinational)          │    │
        │    └───────────────┬───────────────┘    │
        │                    │                     │
        │                    ▼                     │
        │             ┌─────────────┐              │
Clock ──┼────────────→│    State    │              │
        │             │   Register  │              │
        │             └──────┬──────┘              │
        │                    │                     │
        │               Current State              │
        │                    │                     │
        │                    ▼                     │
        │    ┌───────────────────────────────┐    │
        │    │      Output Logic             │    │
        │    │      (Combinational)          │    │
        │    └───────────────┬───────────────┘    │
        │                    │                     │
        └────────────────────┼─────────────────────┘
                             │
                          Output
```

## ۳. State چیست؟ تحلیل عمیق

**State** وضعیت منطقی سیستم در یک لحظه خاص است. State نشان می‌دهد که سیستم در چه مرحله‌ای از فرآیند خود قرار دارد.

### مثال: چراغ راهنمایی

یک چراغ راهنمایی ساده سه State دارد:
```
RED    (قرمز)
GREEN  (سبز)
YELLOW (زرد)
```

سیستم در هر لحظه دقیقاً یکی از این Stateها را دارد.

### مثال: ماشین لباسشویی

یک ماشین لباسشویی ممکن است Stateهای زیر داشته باشد:
```
IDLE      (آماده به کار)
FILL      (پر کردن آب)
WASH      (شستشو)
RINSE     (آبکشی)
SPIN      (خشک‌کنی)
DONE      (اتمام کار)
```

### خصوصیات State

1. **تعداد محدود:** تعداد Stateها همیشه محدود و مشخص است
2. **وضوح:** در هر لحظه سیستم دقیقاً در یک State قرار دارد
3. **حافظه:** State در عناصر حافظه (فلیپ‌فلاپ‌ها) ذخیره می‌شود
4. **قابل شناسایی:** هر State یک نام یا کد منحصر‌به‌فرد دارد

---

## ۴. State Transition — انتقال حالت

**Transition** تغییر از یک State به State دیگر است. Transition معمولاً تحت تأثیر **ورودی‌ها** و **شرایط** خاصی رخ می‌دهد.

### نمایش Transition

```
State_A ──[شرط]──→ State_B
```

### مثال: چراغ راهنمایی با تایمر

```
RED ──[۱۰ ثانیه]──→ GREEN
GREEN ──[۱۰ ثانیه]──→ YELLOW
YELLOW ──[۳ ثانیه]──→ RED
```

### شرایط Transition

Transition می‌تواند به موارد زیر وابسته باشد:
- **ورودی خارجی:** فشار دکمه، سنسور
- **زمان:** تایمر به پایان رسیده
- **مقدار:** شمارنده به مقدار مشخص رسیده
- **ترکیب:** ترکیبی از چند شرط

---

## ۵. State Diagram — نمودار حالت

**State Diagram** یک نمایش گرافیکی از FSM است که Stateها، Transitionها و شرایط آنها را نشان می‌دهد.

### نمادهای State Diagram

```
┌─────────┐
│  STATE  │ ← State
└─────────┘
     │
     │ condition/action ← Transition
     ▼
┌─────────┐
│  STATE  │
└─────────┘
```

### مثال: چراغ راهنمایی کامل

```
                    ┌─────────────────┐
                    │                 │
                    ▼                 │
              ┌───────────┐           │
         ┌───→│   RED     │───────────┘
         │    └───────────┘  (10 sec)
         │         │
         │         │ (10 sec)
         │         ▼
         │    ┌───────────┐
         │    │   GREEN   │
         │    └───────────┘
         │         │
         │         │ (3 sec)
         │         ▼
         │    ┌───────────┐
         └────│  YELLOW   │
              └───────────┘
```

## ۶. State Transition Table — جدول انتقال حالت

**State Transition Table** یک نمایش جدولی از FSM است که برای هر State و ورودی، State بعدی و خروجی را مشخص می‌کند.

### مثال: چراغ راهنمایی (با ورودی تایمر)

| Current State | Timer Done | Next State | Output |
|---------------|------------|------------|--------|
| RED           | 0          | RED        | RED    |
| RED           | 1          | GREEN      | RED    |
| GREEN         | 0          | GREEN      | GREEN  |
| GREEN         | 1          | YELLOW     | GREEN  |
| YELLOW        | 0          | YELLOW     | YELLOW |
| YELLOW        | 1          | RED        | YELLOW |

### مثال: قفل دیجیتال (با ورودی بیت)

| Current State | Input Bit | Next State | Unlocked |
|---------------|-----------|------------|----------|
| IDLE          | 0         | IDLE       | 0        |
| IDLE          | 1         | GOT_1      | 0        |
| GOT_1         | 0         | GOT_10     | 0        |
| GOT_1         | 1         | IDLE       | 0        |
| GOT_10        | 0         | IDLE       | 0        |
| GOT_10        | 1         | GOT_101    | 0        |
| GOT_101       | 0         | IDLE       | 0        |
| GOT_101       | 1         | UNLOCKED   | 1        |
| UNLOCKED      | X         | IDLE       | 0        |

## ۷. Moore در مقابل Mealy — دو نوع اصلی FSM

### ۷.۱. Moore Machine

**تعریف:** در Moore Machine، خروجی فقط به **State فعلی** بستگی دارد.

```
Output = f(Current State)
```

**ساختار:**
```
Input → Next-State Logic → State Register → Output Logic → Output
```

**مثال: چراغ راهنمایی (Moore)**

| State | Output (چراغ‌ها) |
|-------|-----------------|
| RED   | R=1, G=0, Y=0   |
| GREEN | R=0, G=1, Y=0   |
| YELLOW| R=0, G=0, Y=1   |

**مزایا:**
- خروجی پایدارتر (همزمان با State تغییر می‌کند)
- طراحی ساده‌تر
- کمتر در معرض Glitch

**معایب:**
- ممکن است به Stateهای بیشتری نیاز داشته باشد
- خروجی یک لبه Clock بعد از ورودی تغییر می‌کند

---

### ۷.۲. Mealy Machine

**تعریف:** در Mealy Machine، خروجی به **State فعلی و ورودی** بستگی دارد.

```
Output = f(Current State, Input)
```

**ساختار:**
```
Input ──┐
        ├──→ Output Logic ──→ Output
State ──┘
```

**مثال: قفل دیجیتال (Mealy)**

| State | Input | Output (Unlocked) |
|-------|-------|-------------------|
| IDLE  | 0     | 0                 |
| IDLE  | 1     | 0                 |
| ...   | ...   | ...               |
| GOT_101 | 1   | 1                 |

**مزایا:**
- معمولاً به Stateهای کمتری نیاز دارد
- خروجی سریع‌تر به ورودی واکنش نشان می‌دهد

**معایب:**
- خروجی ممکن است ناپایدار باشد (Glitch)
- طراحی پیچیده‌تر

---

### ۷.۳. مقایسه Moore و Mealy

| ویژگی | Moore | Mealy |
|-------|-------|-------|
| **وابستگی خروجی** | فقط State | State + Input |
| **تغییر خروجی** | با تغییر State | با تغییر Input یا State |
| **سرعت واکنش** | کندتر (یک Clock بعد) | سریع‌تر (همان Clock) |
| **تعداد Stateها** | معمولاً بیشتر | معمولاً کمتر |
| **پایداری خروجی** | بیشتر | کمتر (احتمال Glitch) |
| **طراحی** | ساده‌تر | پیچیده‌تر |
| **کاربرد** | سیستم‌های کنترلی | سیستم‌های با سرعت بالا |

---

## ۸. State Encoding — کدگذاری حالت

Stateها باید به صورت باینری در سخت‌افزار ذخیره شوند. روش کدگذاری Stateها تأثیر زیادی بر **مساحت، سرعت و مصرف توان** دارد.

### ۸.۱. Binary Encoding (کدگذاری دودویی)

**تعریف:** هر State با یک عدد باینری معمولی نشان داده می‌شود.

**مثال (۴ State):**
```
S0 = 00
S1 = 01
S2 = 10
S3 = 11
```

**تعداد فلیپ‌فلاپ‌ها:** `ceil(log₂(N))`

**مزایا:**
- حداقل تعداد فلیپ‌فلاپ‌ها
- بهینه از نظر مساحت

**معایب:**
- منطق انتقال حالت پیچیده‌تر
- ممکن است کندتر باشد

---

### ۸.۲. One-Hot Encoding (کدگذاری یک-گرم)

**تعریف:** هر State با یک بیت مجزا نشان داده می‌شود و در هر لحظه دقیقاً یک بیت برابر با ۱ است.

**مثال (۴ State):**
```
S0 = 0001
S1 = 0010
S2 = 0100
S3 = 1000
```

**تعداد فلیپ‌فلاپ‌ها:** N (تعداد Stateها)

**مزایا:**
- منطق انتقال حالت ساده‌تر
- سریع‌تر (کمتر تأخیر)
- تشخیص State آسان‌تر

**معایب:**
- تعداد فلیپ‌فلاپ‌های بیشتر
- مصرف توان بیشتر

---

### ۸.۳. Gray Encoding (کدگذاری گری)

**تعریف:** Stateها با کد گری کدگذاری می‌شوند که در آن Stateهای مجاور فقط یک بیت تفاوت دارند.

**مثال (۴ State):**
```
S0 = 00
S1 = 01
S2 = 11
S3 = 10
```

**مزایا:**
- کاهش نویز در Transitionها
- مفید برای سیستم‌های آنالوگ-دیجیتال

---

### ۸.۴. مقایسه روش‌های Encoding

| روش | فلیپ‌فلاپ‌ها | سرعت | پیچیدگی منطق | مصرف توان |
|-----|------------|------|-------------|-----------|
| Binary | log₂(N) | متوسط | بالا | کم |
| One-Hot | N | بالا | کم | زیاد |
| Gray | log₂(N) | بالا | متوسط | کم |

### در FPGA

در FPGAهای مدرن، ابزار Synthesis معمولاً بهترین روش Encoding را انتخاب می‌کند، اما می‌توان با استفاده از **Attributes** یا **Coding Style** روش مورد نظر را مشخص کرد.

## ۹. State Register — ثبات حالت

**State Register** مجموعه‌ای از فلیپ‌فلاپ‌هاست که State فعلی را ذخیره می‌کند.

### ساختار

```
Next State ──→ [State Register] ──→ Current State
                     ↑
                    Clock
                     ↑
                   Reset
```

### در VHDL

```vhdl
-- State Register
process(clk, reset)
begin
    if reset = '1' then
        state <= IDLE;  -- State اولیه
    elsif rising_edge(clk) then
        state <= next_state;
    end if;
end process;
```

---

## ۱۰. الگوی استاندارد FSM در VHDL — تحلیل کامل

### ساختار سه‌بخشی

یک FSM در VHDL معمولاً به سه بخش تقسیم می‌شود:

1. **State Type Definition:** تعریف Stateها
2. **State Register:** ذخیره State فعلی
3. **Next-State Logic:** محاسبه State بعدی
4. **Output Logic:** تولید خروجی (اختیاری)

### کد کامل

```vhdl
library ieee;
use ieee.std_logic_1164.all;

entity fsm_example is
    port (
        clk     : in  std_logic;
        reset   : in  std_logic;
        start   : in  std_logic;
        done    : out std_logic
    );
end entity;

architecture rtl of fsm_example is
    -- Step 1: Define States
    type state_type is (
        IDLE,
        RUN,
        DONE_STATE
    );
    
    -- Step 2: State signals
    signal state, next_state : state_type;
    
begin
    -- Step 3: State Register (Sequential)
    process(clk, reset)
    begin
        if reset = '1' then
            state <= IDLE;
        elsif rising_edge(clk) then
            state <= next_state;
        end if;
    end process;
    
    -- Step 4: Next-State Logic (Combinational)
    process(state, start)
    begin
        -- Default assignment (prevents latches)
        next_state <= state;
        
        case state is
            when IDLE =>
                if start = '1' then
                    next_state <= RUN;
                end if;
                
            when RUN =>
                -- در اینجا می‌توان شرط پایان را بررسی کرد
                -- مثلاً با یک Counter
                next_state <= DONE_STATE;
                
            when DONE_STATE =>
                next_state <= IDLE;
                
            when others =>
                next_state <= IDLE;
        end case;
    end process;
    
    -- Step 5: Output Logic (Combinational)
    process(state)
    begin
        case state is
            when IDLE =>
                done <= '0';
            when RUN =>
                done <= '0';
            when DONE_STATE =>
                done <= '1';
            when others =>
                done <= '0';
        end case;
    end process;
    
end architecture;
```

## ۱۱. FSM با Counter — ترکیب قدرتمند

### مفهوم

بسیاری از FSMها برای زمان‌بندی به **Counter** نیاز دارند. ترکیب FSM و Counter یکی از رایج‌ترین الگوهای طراحی دیجیتال است.

### ساختار

```
Clock ──→ Counter ──→ Timeout ──→ FSM
                    ──→ Next State
```

### مثال: چراغ راهنمایی با تایمر

```vhdl
architecture rtl of traffic_light is
    type state_type is (RED, GREEN, YELLOW);
    signal state, next_state : state_type;
    signal counter : integer range 0 to 10;
    signal timeout : std_logic;
    
    constant RED_TIME   : integer := 10;
    constant GREEN_TIME : integer := 10;
    constant YELLOW_TIME: integer := 3;
begin
    -- Counter
    process(clk, reset)
    begin
        if reset = '1' then
            counter <= 0;
            timeout <= '0';
        elsif rising_edge(clk) then
            if counter = 0 then
                timeout <= '1';
            else
                counter <= counter - 1;
                timeout <= '0';
            end if;
        end if;
    end process;
    
    -- State Register
    process(clk, reset)
    begin
        if reset = '1' then
            state <= RED;
        elsif rising_edge(clk) then
            state <= next_state;
        end if;
    end process;
    
    -- Next-State Logic
    process(state, timeout)
    begin
        next_state <= state;
        
        case state is
            when RED =>
                if timeout = '1' then
                    next_state <= GREEN;
                    counter <= GREEN_TIME;
                end if;
                
            when GREEN =>
                if timeout = '1' then
                    next_state <= YELLOW;
                    counter <= YELLOW_TIME;
                end if;
                
            when YELLOW =>
                if timeout = '1' then
                    next_state <= RED;
                    counter <= RED_TIME;
                end if;
        end case;
    end process;
    
    -- Output Logic (Moore)
    process(state)
    begin
        case state is
            when RED    => red_light <= '1'; green_light <= '0'; yellow_light <= '0';
            when GREEN  => red_light <= '0'; green_light <= '1'; yellow_light <= '0';
            when YELLOW => red_light <= '0'; green_light <= '0'; yellow_light <= '1';
        end case;
    end process;
end architecture;
```

## ۱۲. Sequence Detector — پروژه کلاسیک

### مفهوم

یک **Sequence Detector** FSM است که یک دنباله خاص از بیت‌ها را در ورودی سریال تشخیص می‌دهد.

### مثال: تشخیص دنباله "1011"

**مسئله:** ورودی سریال را بررسی کنید و هر وقت دنباله "1011" دریافت شد، خروجی ۱ شود.

**State Diagram:**

```
            ┌─────────────────────────────────────┐
            │                                     │
            ▼                                     │
      ┌─────────┐  0   ┌─────────┐  1   ┌─────────┐
      │  IDLE   │─────→│  GOT_1  │─────→│ GOT_10  │
      └─────────┘      └─────────┘      └─────────┘
           │                │                 │
           │ 1              │ 1               │ 0
           ▼                ▼                 ▼
      ┌─────────┐      ┌─────────┐      ┌─────────┐
      │  IDLE   │      │  IDLE   │      │  IDLE   │
      └─────────┘      └─────────┘      └─────────┘
                                                │ 1
                                                ▼
                                          ┌─────────┐
                                          │ UNLOCK  │
                                          └─────────┘
```

**VHDL:**

```vhdl
architecture rtl of seq_detector is
    type state_type is (IDLE, GOT_1, GOT_10, GOT_101, UNLOCKED);
    signal state, next_state : state_type;
begin
    -- State Register
    process(clk, reset)
    begin
        if reset = '1' then
            state <= IDLE;
        elsif rising_edge(clk) then
            state <= next_state;
        end if;
    end process;
    
    -- Next-State Logic
    process(state, input_bit)
    begin
        next_state <= state;
        
        case state is
            when IDLE =>
                if input_bit = '1' then
                    next_state <= GOT_1;
                end if;
                
            when GOT_1 =>
                if input_bit = '0' then
                    next_state <= GOT_10;
                else
                    next_state <= IDLE;  -- 11 باعث ریست می‌شود
                end if;
                
            when GOT_10 =>
                if input_bit = '1' then
                    next_state <= GOT_101;
                else
                    next_state <= IDLE;
                end if;
                
            when GOT_101 =>
                if input_bit = '1' then
                    next_state <= UNLOCKED;
                else
                    next_state <= IDLE;
                end if;
                
            when UNLOCKED =>
                next_state <= IDLE;
                
            when others =>
                next_state <= IDLE;
        end case;
    end process;
    
    -- Output Logic (Mealy)
    process(state, input_bit)
    begin
        if state = GOT_101 and input_bit = '1' then
            detected <= '1';
        else
            detected <= '0';
        end if;
    end process;
end architecture;
```

## ۱۳. FSM در UART — کاربرد واقعی

### UART Transmitter

یک فرستنده UART دنباله زیر را ارسال می‌کند:
1. **Start Bit:** 0
2. **Data Bits:** 8 بیت داده
3. **Stop Bit:** 1

### Stateهای UART Transmitter

```
IDLE → START → DATA0 → DATA1 → ... → DATA7 → STOP → IDLE
```

### VHDL برای UART Transmitter

```vhdl
type tx_state_type is (IDLE, START, DATA, STOP);
signal state, next_state : tx_state_type;
signal bit_counter : integer range 0 to 7;

process(state, start_tx, bit_counter)
begin
    next_state <= state;
    
    case state is
        when IDLE =>
            if start_tx = '1' then
                next_state <= START;
            end if;
            
        when START =>
            next_state <= DATA;
            bit_counter <= 0;
            
        when DATA =>
            if bit_counter = 7 then
                next_state <= STOP;
            else
                bit_counter <= bit_counter + 1;
            end if;
            
        when STOP =>
            next_state <= IDLE;
            
        when others =>
            next_state <= IDLE;
    end case;
end process;
```

## ۱۴. FSM در CPU — واحد کنترل

### مفهوم

واحد کنترل (Control Unit) در یک CPU معمولاً به صورت FSM طراحی می‌شود.

### مراحل اجرای دستور

```
FETCH   (دریافت دستور از حافظه)
   ↓
DECODE  (تفسیر دستور)
   ↓
EXECUTE (اجرای دستور)
   ↓
MEMORY  (دسترسی به حافظه، در صورت نیاز)
   ↓
WRITEBACK (نوشتن نتیجه)
   ↓
FETCH   (دستور بعدی)
```

### ساختار کنترلر FSM

```vhdl
type cpu_state_type is (FETCH, DECODE, EXECUTE, MEMORY, WRITEBACK);
signal state, next_state : cpu_state_type;

process(state, opcode, ready)
begin
    next_state <= state;
    
    case state is
        when FETCH =>
            if ready = '1' then
                next_state <= DECODE;
            end if;
            
        when DECODE =>
            case opcode is
                when ADD_OP | SUB_OP | AND_OP | OR_OP =>
                    next_state <= EXECUTE;
                when LOAD_OP | STORE_OP =>
                    next_state <= MEMORY;
                when JUMP_OP =>
                    next_state <= FETCH;
                when others =>
                    next_state <= FETCH;
            end case;
            
        when EXECUTE =>
            next_state <= WRITEBACK;
            
        when MEMORY =>
            if ready = '1' then
                if opcode = LOAD_OP then
                    next_state <= WRITEBACK;
                else  -- STORE_OP
                    next_state <= FETCH;
                end if;
            end if;
            
        when WRITEBACK =>
            next_state <= FETCH;
            
        when others =>
            next_state <= FETCH;
    end case;
end process;
```

## ۱۵. FSM و Debouncing — اهمیت در FPGA

### مشکل Bounce

کلیدهای مکانیکی هنگام فشار یا رها شدن، چندین بار نوسان می‌کنند (Bounce) که ممکن است باعث چندین Transition ناخواسته در FSM شود.

### راه‌حل: Debouncer

```
Button ──→ Debouncer ──→ FSM
```

### Debouncer با FSM

```vhdl
type deb_state_type is (IDLE, PRESSED, WAIT);
signal deb_state, deb_next_state : deb_state_type;
signal counter : integer range 0 to 255;

process(clk, reset)
begin
    if reset = '1' then
        deb_state <= IDLE;
        debounced <= '0';
    elsif rising_edge(clk) then
        deb_state <= deb_next_state;
        debounced <= '0';
        
        case deb_state is
            when IDLE =>
                if button = '1' then
                    deb_next_state <= PRESSED;
                    counter <= 255;
                end if;
                
            when PRESSED =>
                if counter = 0 then
                    debounced <= '1';
                    deb_next_state <= WAIT;
                else
                    counter <= counter - 1;
                end if;
                
            when WAIT =>
                if button = '0' then
                    deb_next_state <= IDLE;
                end if;
        end case;
    end if;
end process;
```

## ۱۶. اشتباهات رایج در FSM

### اشتباه ۱: فراموش کردن Default Assignment

**نادرست:**
```vhdl
process(state, input)
begin
    case state is
        when IDLE =>
            if input = '1' then
                next_state <= RUN;
            end if;
        when RUN =>
            next_state <= DONE;
        when DONE =>
            next_state <= IDLE;
    end case;
end process;
```

**مشکل:** وقتی در IDLE و input=0، next_state مقدار جدیدی نمی‌گیرد → Latch

**درست:**
```vhdl
process(state, input)
begin
    next_state <= state;  -- Default assignment
    case state is
        when IDLE =>
            if input = '1' then
                next_state <= RUN;
            end if;
        when RUN =>
            next_state <= DONE;
        when DONE =>
            next_state <= IDLE;
    end case;
end process;
```

### اشتباه ۲: استفاده از Clock در Next-State Logic

**نادرست:**
```vhdl
process(clk)  -- نباید Clock داشته باشد
begin
    if rising_edge(clk) then
        case state is
            ...
        end case;
    end if;
end process;
```

**درست:**
```vhdl
process(state, input)  -- فقط ورودی‌ها
begin
    case state is
        ...
    end case;
end process;
```

### اشتباه ۳: فراموش کردن Reset

**نادرست:**
```vhdl
process(clk)
begin
    if rising_edge(clk) then
        state <= next_state;
    end if;
end process;
```

**درست:**
```vhdl
process(clk, reset)
begin
    if reset = '1' then
        state <= IDLE;
    elsif rising_edge(clk) then
        state <= next_state;
    end if;
end process;
```

### اشتباه ۴: Stateهای بیش از حد

گاهی ممکن است با Stateهای زیاد، طراحی پیچیده شود. در این موارد:
- از **FSM با زیر-State** استفاده کنید
- از **Counter** برای کاهش Stateها استفاده کنید
- طراحی را به چند FSM کوچک‌تر تقسیم کنید

```
Digital Logic
      ↓
Logic Gates
      ↓
Boolean Algebra
      ↓
Truth Tables
      ↓
Combinational Circuits
      ↓
     ├── MUX

      ↓

      ↓
Digital System Design
      ↓
CPU Design
      ↓

```

### ارتباط با مباحث قبلی

```
FSM = State Register + Next-State Logic + Output Logic

State Register ← از مباحث Flip-Flop و Register
Next-State Logic ← از مباحث Combinational Logic
Output Logic ← از مباحث Combinational Logic
Counter ← از مباحث Counter
```

## ۲۰. جمع‌بندی نهایی

### آنچه باید به خاطر بسپارید

**۱. تعریف اصلی:**
> **FSM = سیستمی با تعداد محدودی State که بر اساس ورودی و State فعلی، State بعدی و خروجی را تعیین می‌کند**

**۲. چهار بخش اصلی:**
- **State:** وضعیت فعلی
- **Input:** ورودی‌های خارجی
- **Next State:** حالت بعدی
- **Output:** خروجی‌ها

**۳. دو نوع اصلی:**
- **Moore:** خروجی فقط به State وابسته است
- **Mealy:** خروجی به State + Input وابسته است

**۴. سه روش Encoding:**
- **Binary:** کمترین فلیپ‌فلاپ
- **One-Hot:** ساده‌ترین منطق
- **Gray:** کاهش نویز

**۵. الگوی VHDL:**
```vhdl
type state_type is (...);
signal state, next_state : state_type;

-- State Register
process(clk, reset)
begin
    if reset = '1' then
        state <= IDLE;
    elsif rising_edge(clk) then
        state <= next_state;
    end if;
end process;

-- Next-State Logic
process(state, input)
begin
    next_state <= state;
    case state is
        when IDLE =>
            if input = '1' then
                next_state <= RUN;
            end if;
        ...
    end case;
end process;

-- Output Logic
process(state)  -- Moore
begin
    ...
end process;
```

### پیام نهایی

FSM نقطه عطفی در یادگیری طراحی دیجیتال است. با تسلط بر FSM، شما می‌توانید:
- **سیستم‌های کنترلی** طراحی کنید
- **پروتکل‌های ارتباطی** پیاده‌سازی کنید
- **پردازنده‌های ساده** بسازید
- **سیستم‌های تعبیه‌شده** طراحی کنید

> **Combinational Logic تصمیم می‌گیرد چه اتفاقی باید بیفتد؛ Sequential Logic به خاطر می‌سپارد که سیستم در چه وضعیتی قرار دارد؛ FSM این دو را برای ساختن رفتار یک سیستم دیجیتال به هم متصل می‌کند.**
