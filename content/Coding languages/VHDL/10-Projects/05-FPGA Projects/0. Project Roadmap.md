# Level 6 — Advanced VHDL

تا اینجا شما یاد گرفته‌اید با VHDL مدار و سیستم دیجیتال بسازید. در Level 5 حتی توانستید چند بخش را با هم ترکیب کنید و سیستم‌هایی مثل Clock، Stopwatch، PWM و UART بسازید.

اما یک مشکل جدید به وجود می‌آید:

وقتی پروژه‌ها بزرگ می‌شوند، اگر همه‌چیز را در یک فایل و با کد تکراری بنویسید، طراحی خیلی سریع پیچیده و غیرقابل‌مدیریت می‌شود.

هدف Level 6 این است که یاد بگیرید:

> **چطور VHDL را به شکل حرفه‌ای، قابل استفاده مجدد، قابل توسعه و ماژولار بنویسید.**

---

# Project 51 — Generic Counter

## هدف پروژه

تا الان اگر یک Counter هشت‌بیتی می‌ساختید، احتمالاً اندازه آن مستقیماً داخل کد مشخص بود.

مثلاً یک Counter:

```text
8-bit
```

اما اگر فردا Counter شانزده‌بیتی بخواهید چه؟

نباید دوباره کل کد را بنویسید.

در این پروژه یاد می‌گیرید یک Counter بسازید که اندازه آن **قابل تنظیم** باشد.

---

## ایده اصلی

به جای اینکه بگویید:

```text
Counter = 8-bit
```

می‌گویید:

```text
Counter Width = Parameter
```

مثلاً:

```text
WIDTH = 4
```

یا:

```text
WIDTH = 8
```

یا:

```text
WIDTH = 16
```

---

## چیزی که می‌سازید

یک Component:

```text
Generic Counter
```

که بتواند در پروژه‌های مختلف استفاده شود.

---

## چه چیزی یاد می‌گیرید؟

- Generic
    
- Parameterization
    
- Reusable Design
    
- `numeric_std`
    
- `unsigned`
    
- Hardware Scalability
    

---

## از شما چه می‌خواهد؟

باید Counter را طوری طراحی کنید که حداقل این موارد قابل تنظیم باشند:

```text
WIDTH
```

و ترجیحاً:

```text
MAX_VALUE
```

همچنین باید مشخص کنید:

```text
Reset
Enable
Clock
```

چه رفتاری دارند.

---

## نتیجه

در پایان باید بتوانید:

```text
Generic Counter
      │
      ├── WIDTH = 4
      ├── WIDTH = 8
      └── WIDTH = 16
```

را بدون تغییر اساسی در Architecture استفاده کنید.

# Project 53 — Generic FIFO

این پروژه سخت‌تر است.

## هدف پروژه

ساخت یک FIFO قابل تنظیم.

FIFO یعنی:

> First In, First Out

یعنی اولین داده‌ای که وارد می‌شود، اولین داده‌ای است که خارج می‌شود.

---

## مثال

اگر این داده‌ها را وارد کنید:

```text
A
B
C
D
```

باید به همین ترتیب خارج شوند:

```text
A
B
C
D
```

---

## ساختار مفهومی

```text
WRITE
  ↓
┌─────────────┐
│ FIFO        │
│             │
│ A           │
│ B           │
│ C           │
│ D           │
└─────────────┘
       ↓
     READ
```

---

## پارامترها

FIFO باید حداقل دو پارامتر داشته باشد:

```text
DATA_WIDTH
DEPTH
```

مثلاً:

```text
DATA_WIDTH = 8
DEPTH = 16
```

یا:

```text
DATA_WIDTH = 32
DEPTH = 64
```

---

## باید وضعیت‌های FIFO را هم مدیریت کنید

مثلاً:

```text
empty
full
```

و در طراحی بهتر:

```text
almost_empty
almost_full
```

---

## چه چیزی یاد می‌گیرید؟

- Generic
    
- Array
    
- Memory
    
- Read Pointer
    
- Write Pointer
    
- Full / Empty Detection
    
- Modular Design
    

---

## از شما چه می‌خواهد؟

باید بتوانید:

```text
write
read
full
empty
```

را به شکل درست مدیریت کنید.

همچنین باید موارد مرزی را تست کنید:

```text
Read from Empty FIFO
Write to Full FIFO
Write → Read
Multiple Writes
Multiple Reads
Reset
```

# Project 54 — Custom Data Types

## هدف پروژه

VHDL فقط `std_logic` و `std_logic_vector` نیست.

در این پروژه یاد می‌گیرید Typeهای مخصوص سیستم خودتان بسازید.

---

## مثال

برای FSM قبلاً ممکن بود State را به شکل خاص تعریف کنید:

```text
IDLE
RUNNING
DONE
ERROR
```

این‌ها می‌توانند یک **Enumerated Type** باشند.

---

## هدف

به جای اینکه Stateها را به صورت عددهای نامفهوم نگه دارید:

```text
00
01
10
11
```

از نام‌های معنادار استفاده کنید:

```text
IDLE
RUNNING
DONE
ERROR
```

---

## چه چیزی یاد می‌گیرید؟

- Enumerated Types
    
- User-Defined Types
    
- Type Safety
    
- Readable RTL
    
- State Modeling
    

---

## از شما چه می‌خواهد؟

یک FSM طراحی کنید که Type مخصوص خودش را داشته باشد.

مثلاً:

```text
IDLE
START
PROCESS
DONE
ERROR
```

بعد Transitionهای آن را پیاده‌سازی کنید.

# Project 55 — Record-Based System

## هدف پروژه

حالا یک مرحله جلوتر می‌روید.

گاهی یک Component ورودی‌ها و خروجی‌های زیادی دارد.

مثلاً:

```text
valid
ready
data
error
busy
start
done
```

اگر همه را جداگانه منتقل کنید، Interface شلوغ می‌شود.

در این پروژه با **Record** آشنا می‌شوید.

---

## مفهوم

چند Signal مرتبط را داخل یک ساختار منطقی قرار می‌دهید.

مثلاً:

```text
Transaction
│
├── data
├── valid
├── ready
└── error
```

---

## هدف پروژه

ساخت یک Component که Interface آن از Record استفاده کند.

---

## چه چیزی یاد می‌گیرید؟

- Records
    
- Structured Interfaces
    
- Data Organization
    
- Cleaner RTL
    
- Interface Abstraction
    

---

## از شما چه می‌خواهد؟

یک سیستم کوچک بسازید که مثلاً یک Data Packet داشته باشد:

```text
data
valid
ready
```

و این اطلاعات را به صورت یک Record منتقل کند.

---

- Project Architecture

```text
Constants
Custom Types
Function
```

باشد.

بعد چند Component مختلف از همان Package استفاده کنند.

# Project 58 — Generate-Based Hardware

این پروژه مفهوم بسیار مهمی دارد.

## هدف پروژه

مثلاً:

```text

```


---

## ایده

با `generate` می‌توانید ساختارهای تکراری Hardware را ایجاد کنید.

مثلاً:

```text
Generate
   ↓
Register 0
Register 1
Register 2
...
Register 7
```

---

## چه چیزی یاد می‌گیرید؟

- Generate
    
- Hardware Replication
    
- Generate-for
    
- Generate-if
    
- Scalable Architecture
    

---

## از شما چه می‌خواهد؟

یک سیستم بسازید که تعداد مشخصی Component را با یک Parameter ایجاد کند.

مثلاً:

```text
N = 8
```

یعنی 8 واحد.

و:

```text
N = 16
```

یعنی 16 واحد.

# چیزی که در Level 6 باید تغییر کند

در Levelهای قبلی سؤال اصلی این بود:

> «چطور این مدار را بسازم؟»

در Level 6 سؤال تبدیل می‌شود به:

> **«چطور این مدار را طوری بسازم که بتوانم بارها و در پروژه‌های مختلف از آن استفاده کنم؟»**

این تفاوت بسیار مهم است.

---

# یک مثال واقعی

فرض کنید در Level 3 یک Counter ساختید:

```text
Counter
```

در Level 6 همان Counter را تبدیل می‌کنید به:

```text
Generic Counter
```

بعد:

```text
Generic Counter
      ↓
Package
      ↓
Component
      ↓
Hierarchy
      ↓
Reusable Library
```

حالا در پروژه Digital Clock:

```text
Hours Counter
Minutes Counter
Seconds Counter
```

همه می‌توانند از همان Component استفاده کنند.

# در پایان Level 6 باید چه دیدی داشته باشید؟

باید بتوانید یک پروژه را این‌طور ببینید:

```text
                    TOP LEVEL
                        │
        ┌───────────────┼───────────────┐
        ↓               ↓               ↓
   Controller        Datapath       Interface
        │               │               │
        ↓               ↓               ↓
       FSM           Registers        UART
        │               │
        ↓               ↓
     Counter            ALU
        │
        ↓
     Timer
```

و برای هر بخش بتوانید بگویید:

```text
این Component چیست؟
چه Interfaceای دارد؟
چه Genericهایی دارد؟
چه Typeهایی استفاده می‌کند؟
از چه Packageای استفاده می‌کند؟
چطور Test می‌شود؟
آیا در پروژه بعدی قابل استفاده مجدد است؟
```

---

## دستاورد اصلی Level 6

بعد از این Level شما دیگر فقط **VHDL programmer** نیستید؛ باید کم‌کم مثل یک **RTL Designer** فکر کنید.

یعنی:

```text
Requirement
    ↓
Architecture
    ↓
Components
    ↓
Interfaces
    ↓
Reusable RTL
    ↓
Verification
```

و این دقیقاً نقطه‌ای است که ورود به **Level 7 — Verification & Testbench** معنی پیدا می‌کند؛ چون حالا Componentهای نسبتاً حرفه‌ای دارید و باید یاد بگیرید چگونه آن‌ها را **سیستماتیک، خودکار و قابل اعتماد تست و Verify** کنید.
