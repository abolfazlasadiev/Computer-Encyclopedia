# VHDL در مقابل SystemVerilog

## مقدمه

**VHDL** و **SystemVerilog** دو زبان مهم در طراحی و Verification سیستم‌های دیجیتال هستند.

هر دو زبان می‌توانند برای:

- طراحی RTL
    
- Simulation
    
- Verification
    
- FPGA Development
    
- ASIC Development
    

استفاده شوند.

اما این دو زبان از دو مسیر متفاوت تکامل پیدا کرده‌اند.

VHDL از ابتدا به‌عنوان یک **Hardware Description Language استاندارد و strongly typed** توسعه یافت، در حالی که SystemVerilog توسعه‌ای بر پایه Verilog است که علاوه بر RTL Design، امکانات گسترده‌ای برای **Verification** ارائه می‌کند.

به‌صورت ساده:

```text
VHDL
  │
  ├── Hardware Description
  ├── Strong Typing
  ├── ساختار صریح
  └── RTL / FPGA / ASIC


SystemVerilog
  │
  ├── Hardware Description
  ├── RTL Design
  ├── Verification
  ├── Assertions
  ├── Interfaces
  └── Object-Oriented Verification
```

---

# 1. VHDL چیست؟

VHDL مخفف:

> VHSIC Hardware Description Language

است.

VHDL برای توصیف ساختار و رفتار سیستم‌های دیجیتال طراحی شده است.

استاندارد اصلی آن:

> **IEEE 1076**

است.

VHDL در طول زمان نسخه‌های مختلفی مانند:

```text
VHDL-87
VHDL-93
VHDL-2000
VHDL-2002
VHDL-2008
VHDL-2019
```

داشته است.

---

# 2. SystemVerilog چیست؟

SystemVerilog یک زبان توسعه‌یافته بر پایه Verilog است.

این زبان برای ترکیب دو نیاز مهم توسعه پیدا کرد:

```text
RTL Design
     +
Hardware Verification
```

SystemVerilog امکاناتی را برای طراحی Hardware ارائه می‌کند و در عین حال قابلیت‌های قدرتمندی برای Verification دارد.

استاندارد SystemVerilog در خانواده استانداردهای IEEE 1800 قرار دارد.

# 5. یک AND Gate ساده

### VHDL

```vhdl
library ieee;
use ieee.std_logic_1164.all;

entity and_gate is
    port (
        a : in  std_logic;
        b : in  std_logic;
        y : out std_logic
    );
end entity;

architecture rtl of and_gate is
begin
    y <= a and b;
end architecture;
```

### SystemVerilog

```systemverilog
module and_gate (
    input  logic a,
    input  logic b,
    output logic y
);

assign y = a & b;

endmodule
```

از دید Hardware:

```text
A ─────┐
       │
       AND ───── Y
       │
B ─────┘
```

هر دو زبان می‌توانند همین مدار را توصیف کنند.

# 6. Entity و Module

در VHDL معمولاً Interface با `entity` تعریف می‌شود:

```vhdl
entity counter is
    port (
        clk : in  std_logic;
        q   : out std_logic
    );
end entity;
```

و Implementation در `architecture` قرار می‌گیرد:

```vhdl
architecture rtl of counter is
begin
    ...
end architecture;
```

در SystemVerilog معمولاً از `module` استفاده می‌شود:

```systemverilog
module counter (
    input  logic clk,
    output logic q
);

...

endmodule
```

بنابراین:

```text
VHDL
Entity + Architecture

SystemVerilog
Module
```

# 7. Type System

یکی از مهم‌ترین تفاوت‌های VHDL و SystemVerilog در سیستم Type آن‌هاست.

VHDL یک زبان strongly typed است.

مثلاً:

```vhdl
signal a     : std_logic;
signal data  : std_logic_vector(7 downto 0);
signal count : unsigned(7 downto 0);
```

این Typeها از یکدیگر متمایز هستند.

در SystemVerilog نیز سیستم Type بسیار قدرتمندتر از Verilog کلاسیک شده است.

مثلاً:

```systemverilog
logic        a;
logic [7:0]  data;
int unsigned count;
```

SystemVerilog همچنین قابلیت‌هایی مانند:

- `typedef`
    
- `enum`
    
- `struct`
    
- `union`
    
- `class`
    

را ارائه می‌کند.

# 8. std_logic در برابر logic

در VHDL معمولاً برای سیگنال‌های دیجیتال از:

```vhdl
std_logic
```

استفاده می‌شود.

مثلاً:

```vhdl
signal clk : std_logic;
```

در SystemVerilog معمولاً:

```systemverilog
logic clk;
```

استفاده می‌شود.

اما این دو Type دقیقاً معادل یکدیگر نیستند.

در VHDL، `std_logic` یک Type منطقی چندحالته است.

SystemVerilog نیز مدل‌های مختلفی برای سیگنال‌ها و حالت‌های منطقی دارد، اما مدل Type و Resolution آن متفاوت است.

بنابراین نباید صرفاً این دو را از نظر Syntax معادل در نظر گرفت.

# 10. Process و always_ff

برای Sequential Logic در VHDL معمولاً از `process` استفاده می‌شود:

```vhdl
process(clk)
begin
    if rising_edge(clk) then
        q <= d;
    end if;
end process;
```

در SystemVerilog روش مدرن و صریح‌تر:

```systemverilog
always_ff @(posedge clk) begin
    q <= d;
end
```

است.

هر دو می‌توانند یک D Flip-Flop را توصیف کنند.

```text
        ┌──────────┐
D ─────►│ D Flip   │────► Q
        │  Flop    │
CLK ───►│          │
        └──────────┘
```

# 11. Combinational Logic

در VHDL می‌توان منطق ترکیبی را به‌صورت Concurrent بیان کرد:

```vhdl
y <= a and b;
```

یا داخل یک Process:

```vhdl
process(all)
begin
    if sel = '1' then
        y <= a;
    else
        y <= b;
    end if;
end process;
```

در SystemVerilog می‌توان از:

```systemverilog
always_comb begin
    if (sel)
        y = a;
    else
        y = b;
end
```

استفاده کرد.

`always_comb` به‌صورت صریح مشخص می‌کند که هدف Process، منطق ترکیبی است.

# 13. Generic در برابر Parameter

در VHDL برای قابل تنظیم کردن طراحی از `generic` استفاده می‌شود:

```vhdl
entity counter is
    generic (
        WIDTH : positive := 8
    );

    port (
        clk : in std_logic;
        q   : out unsigned(WIDTH-1 downto 0)
    );
end entity;
```

در SystemVerilog:

```systemverilog
module counter #(
    parameter int WIDTH = 8
) (
    input  logic             clk,
    output logic [WIDTH-1:0] q
);
```

هدف هر دو:

```text
یک طراحی
    ↓
قابل تنظیم
    ↓
قابل استفاده مجدد
```

است.

# 14. Package در برابر Package

هر دو زبان مفهوم `package` دارند.

در VHDL می‌توان Typeها، Constantها، Functionها و Procedureها را در Package قرار داد.

مثلاً:

```vhdl
package my_package is

    constant DATA_WIDTH : integer := 32;

end package;
```

در SystemVerilog نیز:

```systemverilog
package my_package;

    parameter int DATA_WIDTH = 32;

endpackage
```

اما Package در SystemVerilog بخشی از یک اکوسیستم بزرگ‌تر برای Design و Verification است.

# 15. Enumeration و State Machine

هر دو زبان برای FSM بسیار مناسب هستند.

در VHDL می‌توان Stateها را به‌صورت Enumeration تعریف کرد:

```vhdl
type state_type is (
    IDLE,
    START,
    RUN,
    DONE
);

signal state : state_type;
```

این روش یکی از نقاط قوت VHDL است؛ زیرا Stateها به‌صورت Type مشخص تعریف می‌شوند.

در SystemVerilog:

```systemverilog
typedef enum logic [1:0] {
    IDLE,
    START,
    RUN,
    DONE
} state_t;

state_t state;
```

SystemVerilog نیز این مفهوم را به‌شکل بسیار خوبی پشتیبانی می‌کند.

# 16. Assertions

یکی از زمینه‌هایی که SystemVerilog بسیار قدرتمند است، Verification است.

SystemVerilog دارای **SystemVerilog Assertions (SVA)** است.

برای مثال می‌توان یک Property تعریف کرد که رفتار خاصی باید همیشه برقرار باشد.

به‌صورت مفهومی:

```text
اگر Request فعال شد
        ↓
باید در مدت مشخصی
        ↓
Response دریافت شود
```

این نوع بررسی‌ها برای Verification سیستم‌های پیچیده بسیار مهم هستند.

VHDL نیز قابلیت Assertion دارد:

```vhdl
assert condition
    report "Error"
    severity error;
```

اما امکانات Assertion در SystemVerilog، به‌خصوص در قالب SVA، بسیار گسترده‌تر است.

# 21. Interface

SystemVerilog مفهوم `interface` را ارائه می‌کند.

Interface اجازه می‌دهد گروهی از سیگنال‌های مرتبط در یک ساختار واحد قرار گیرند.

مثلاً:

```systemverilog
interface bus_if;

    logic        clk;
    logic        valid;
    logic        ready;
    logic [31:0] data;

```

این ویژگی برای مدیریت ارتباطات پیچیده بین بخش‌های مختلف Design و Testbench بسیار مفید است.

VHDL نیز روش‌های مختلفی برای ساخت Interfaceهای پیچیده دارد، اما مدل `interface` در SystemVerilog یکی از ویژگی‌های مشخص آن است.

# 28. حجم کد

به‌صورت کلی، VHDL معمولاً نسبت به SystemVerilog verboseتر است.

مثلاً برای تعریف یک Module ساده، VHDL ممکن است کلمات بیشتری نیاز داشته باشد.

در مقابل SystemVerilog معمولاً اجازه می‌دهد همان مفهوم با Syntax کوتاه‌تری بیان شود.

اما کوتاه‌تر بودن همیشه به معنی بهتر بودن نیست.

```text
کد کمتر
   ≠
کد بهتر
```

در پروژه‌های بزرگ، خوانایی، قابلیت نگهداری و جلوگیری از خطا اهمیت بیشتری دارند.

# 30. مزایای VHDL

VHDL نقاط قوت مهمی دارد:

### 1. Type System قوی

به جلوگیری از برخی خطاهای طراحی کمک می‌کند.

### 2. ساختار صریح

ساختار Entity و Architecture طراحی را واضح می‌کند.

### 3. سابقه طولانی

VHDL سال‌ها در پروژه‌های صنعتی استفاده شده است.

### 4. استاندارد IEEE

زبان یک استاندارد رسمی و شناخته‌شده دارد.

### 5. مناسب برای آموزش RTL

VHDL برای یادگیری مفاهیم Hardware بسیار مناسب است.

### 6. مناسب برای پروژه‌های بزرگ

با Coding Style مناسب، ساختار VHDL می‌تواند برای پروژه‌های بزرگ بسیار قابل نگهداری باشد.

---

# 31. مزایای SystemVerilog

SystemVerilog نیز مزایای مهمی دارد:

### 1. Syntax مختصر

معمولاً برای بیان RTL به کد کمتری نیاز دارد.

### 2. RTL قدرتمند

برای طراحی‌های مدرن دیجیتال بسیار مناسب است.

### 3. Verification پیشرفته

شامل امکاناتی مانند:

```text
Assertions
Randomization
Coverage
Classes
```

است.

### 4. Interface

برای طراحی و Verification ارتباطات پیچیده بسیار مفید است.

### 5. UVM

SystemVerilog زبان اصلی بسیاری از Verification Environmentهای مبتنی بر UVM است.

### 6. یک زبان برای Design و Verification

می‌توان RTL و بخش بزرگی از Verification را در یک اکوسیستم زبانی مدیریت کرد.

---

# 32. کدام‌یک بهتر است؟

پاسخ مطلقی وجود ندارد.

اگر سؤال این باشد:

> «برای یادگیری Hardware و FPGA کدام را انتخاب کنم؟»

VHDL انتخاب بسیار خوبی است.

اگر سؤال این باشد:

> «برای Verification پیچیده ASIC کدام امکانات بیشتری دارد؟»

SystemVerilog معمولاً انتخاب قدرتمندتری است.

اگر سؤال این باشد:

> «کدام زبان بهتر است؟»

پاسخ:

> **به پروژه، تیم و ابزارها بستگی دارد.**

---

# 33. آیا یادگیری VHDL بعداً یادگیری SystemVerilog را سخت می‌کند؟

خیر.

اتفاقاً اگر VHDL را به‌صورت اصولی یاد بگیرید، بسیاری از مفاهیم اصلی Hardware را خواهید آموخت:

```text
Digital Logic
     ↓
RTL
     ↓
Clock
     ↓
Reset
     ↓
Register
     ↓
FSM
     ↓
Memory
     ↓
Interface
     ↓
Verification
```

این مفاهیم وابسته به یک زبان خاص نیستند.

بعداً می‌توانید همان مفهوم را با SystemVerilog بیان کنید.

# 34. چیزی که باید از مقایسه یاد بگیریم

هدف از این مقایسه این نیست که دانشجو مجبور شود بین VHDL و SystemVerilog یکی را انتخاب کند.

هدف این است که بفهمد:

> **زبان فقط ابزار بیان یک طراحی Hardware است.**

برای مثال:

```text
مسئله
 ↓
طراحی دیجیتال
 ↓
Architecture
 ↓
RTL
 ↓
VHDL
```

یا:

```text
مسئله
 ↓
طراحی دیجیتال
 ↓
Architecture
 ↓
RTL
 ↓
SystemVerilog
```

در هر دو مسیر، Hardware Concept می‌تواند یکسان باشد.

```text
      ↓

      ↓
```

در مرحله پیشرفته‌تر می‌توان همین پروژه‌ها را دوباره با SystemVerilog پیاده‌سازی کرد:

```text
   ↓

```

و تفاوت دو زبان را در یک **Hardware واقعی** مشاهده کرد.

# 36. جمع‌بندی

VHDL و SystemVerilog هر دو زبان‌های قدرتمند طراحی Hardware هستند، اما نقاط تمرکز متفاوتی دارند.

VHDL بیشتر با:

```text
Strong Typing
Explicit Structure
Readability
Maintainability
IEEE Standardization
```

شناخته می‌شود.

SystemVerilog علاوه بر RTL، امکانات بسیار قدرتمندی برای:

```text
Verification
Assertions
Randomization
Coverage
Classes
Interfaces
UVM
```

ارائه می‌کند.

بنابراین می‌توان تفاوت کلی را این‌گونه خلاصه کرد:

```text
VHDL
 │
 ├── Hardware Description
 ├── RTL
 ├── FPGA
 ├── ASIC
 ├── Strong Typing
 └── Structured Design


SystemVerilog
 │
 ├── Hardware Description
 ├── RTL
 ├── FPGA
 ├── ASIC
 ├── Advanced Verification
 ├── Assertions
 ├── Randomization
 ├── Coverage
 └── UVM
```

و مهم‌ترین اصل:

> **اول Hardware را یاد بگیر، بعد زبان را.**

اگر دانشجو بداند یک Counter، FSM، UART یا CPU چگونه در Hardware ساخته می‌شود، یادگیری آن با VHDL یا SystemVerilog بیشتر به یادگیری Syntax و Coding Style تبدیل خواهد شد، نه یادگیری دوباره مفهوم Hardware.
